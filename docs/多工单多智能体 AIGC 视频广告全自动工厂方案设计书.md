

## 一、 项目背景与核心挑战

本方案旨在构建一套从底层工单（如游戏、电商等广告投放需求）直达高转化率广告视频/图片产出的自动化全链路 AIGC 流水线。

传统的线性 AIGC 流水线（选题 -> 文案 -> 脚本 -> 图片 -> 视频）存在以下核心痛点：

1. **误差累积：** 前置节点（如选题）的微小偏差，会导致最终生成的视频完全不可用。
2. **风控高危：** 针对特定出海市场（如印度等网赚/游戏类产品）以及特定事件（如“首充”），若直接暴露暴富或现金元素，极易触发 Facebook (Meta) 等媒体的严苛风控规则，导致批量封号。
3. **视觉低幼：** AI 默认生成的画面易带有强烈的“二次元、塑料 3D 或美漫儿童风”，对 18-65 岁且对利益敏感的成熟受众缺乏说服力。
4. **多工单扩展难：** 无法在保障各项目专属视觉资产（UI、Logo）和本地化风俗的同时，支持成百上千个工单的高并发流水线生产。

本设计通过引入**“带反思与反馈的循环生成架构”**以及**“解耦的动态配置多智能体（Multi-Agent）编排”**，从根本上解决上述落地痛点。

## 二、 系统总体架构设计

系统放弃传统的单向线性代码链条，采用基于图结构的工作流框架（如 LangGraph）进行多智能体编排。核心思想是将工单数据定义为全局状态（State），各生成与审核节点作为图的节点（Nodes），通过条件路由实现自动化重试与熔断。

```
[原始工单输入] -> (1. 工单解析网关) -> 初始化全局 State
                                      │
            ┌─────────────────────────┴────────────────────────┐
            ▼                                                  ▼
     [游戏/网赚类路由]                                   [电商/社交类路由]
            │                                                  │
    (2. 动态挂载项目资产)                              (2. 动态挂载项目资产)
   (LoRA/UI/地区风俗知识库)                            (LoRA/UI/地区风俗知识库)
            │                                                  │
            └─────────────────────────┬────────────────────────┘
                                      ▼
                             (3. 选题与文案生成) <───┐
                                      │              │
                                  [文案审核] ──(不通过)┘
                                      │(通过)
                                      ▼
                             (4. 结构化分镜脚本) <───┐
                                      │              │
                                  [脚本审核] ──(不通过)┘
                                      │(通过)
                                      ▼
                             (5. 精准控图与垫图)
                                      │
                             (6. 异步视频流渲染)
                                      │
                                      ▼
                             (7. 多模态合规审计) ───(不通过)─> [人工异常介入队列]
                                      │(通过)
                                      ▼
                             (8. 人机协同看板确认)
                                      │(Approve)
                                      ▼
                                [正式上架投放] ──> 数据回传(CPM/转化率) ──> 沉淀专属 Skill
```

## 三、 核心节点质量控制策略



### 3.1 选题与文案层：深度本地化与前置风控拦截

- **双模型博弈机制：** 设立生成模型（Generator）与评估模型（Evaluator）。Evaluator 模拟挑剔的广告优化师或媒体审核员进行打分。
- **深度本地化约束：** 根据投放国家（如印度），自动向系统提示词注入本地语感约束（如使用印地语与英语混合的 Hinglish），强调“高回报、低门槛首充、即时反馈”，直击目标群体痛点。
- **前置风控拦截：** 严禁出现绝对化高额回报承诺及敏感诱导词，在文本层阻断违规因子。



### 3.2 视频脚本层：结构化分镜拆解

拒绝纯文本脚本输出，强制要求脚本生成智能体输出高度结构化的 JSON 数据，以精准指导下游的多模态生成：

```json
{
  "scene_id": 1,
  "duration_seconds": 3,
  "visual_description_prompt": "Hyper-realistic close-up of a mature Indian driver smiling in his car, holding a smartphone, cinematic lighting, realistic skin texture, 85mm lens --no cartoon, anime, claymation",
  "camera_motion": "Slow zoom in",
  "voiceover_text": "बस एक क्लिक और शुरू करें अपनी किस्मत का खेल।",
  "onscreen_text": "Instant Bonus on First Charge",
  "audio_effect": "Subtle coins clinking sound"
}
```

- **前3秒黄金法则：** 限制前 3 秒必须具备强视觉冲击或痛点悬念，以降低划屏率。



### 3.3 图像与视频生成层：完美契合产品与去低幼化

- **UI 资产提取与绿幕合成（UI Compositing）：** 严禁让 AI 直接生成产品的游戏或应用界面（避免幻觉）。系统生成“人持手机、桌面置手机”的实景底图，再利用代码或专用工作流节点，将真实的系统网页/APK 高清 UI 截图通过透视匹配（Perspective Match）无缝贴入手机屏幕，实现 100% 产品还原。
- **训练专属 LoRA 模型：** 为每个项目沉淀 20-30 张高清视觉资产（Logo、特殊 UI、吉祥物），训练项目专属 LoRA，确保全局元素与产品视觉深度咬合。
- **去低幼化反向提示词工程：**
  - *Negative Prompt:* `cartoon, 3d render, anime, childish, claymation, plastic, low res, fake, toy`
  - *Positive Prompt:* `hyper-realistic, cinematic lighting, professional photography, realistic skin texture, mature demographic`
- **微动态控制（Motion Control）：** 图生视频时，严格限制动作幅度（Motion Scale 控制在低阈值）。避免大范围动作导致的人脸扭曲和“AI 异形”产生。侧重于镜头的推拉、人物面部微表情（如挑眉、微笑）及真实的 UI 闪烁、粒子特效。

## 四、 多工单高扩展性设计

为了支撑成百上千个不同工单并发，系统实现全面解耦，依赖底层关系型数据库（如 PostgreSQL）及向量库进行动态参数挂载。

### 4.1 统一的工单解析网关

系统入口对接收到的任意非结构化工单进行清洗，转化为统一的全局 State 状态总线：

```json
{
  "work_order_id": "WO-20260626-777",
  "project_name": "GAJA777",
  "target_country": "IN",
  "timezone": "GMT+7",
  "media": "Facebook",
  "event_type": "first_charge",
  "audience_age_min": 18,
  "audience_age_max": 65,
  "landing_page": "https://www.gaja777.game/#/?invite=YBG71118&register=true"
}
```



### 4.2 动态业务知识库与资产挂载

基于 State 中的参数，系统在运行时动态加载关联的元数据：

1. **根据** `target_country` **挂载地区风俗库：** 自动补充特定语言风格、当地忌讳手势、高转化色彩偏好（如印度偏好金色与强视觉刺激）。
2. **根据** `project_name` **挂载资产路由：** 自动拉取该项目专属的 LoRA ID、UI 切图素材库、品牌色十六进制值等。



### 4.3 独立的合规与风控审计 Skill

从生成模型中剥离审计职责，设立独立的**合规诊断助理**。该模块通过多模态大模型（VLM，如 Gemini Pro Vision）对生成的文案、分镜截图进行全盘扫描，不对 Meta 的隐藏评分做盲目猜测，而是严格基于可见证据对照 Meta 广告标准（Advertising Standards）输出结构化诊断：

```json
{
  "severity": "high",
  "category": "policy_rejection",
  "evidence": [
    "画面中包含过于逼真的大额真钞卢比堆砌",
    "字幕含有绝对化高额回报暗示"
  ],
  "likely_reason": "涉嫌规避系统或不真实的赚钱声明（Misleading Claims）",
  "recommended_action": [
    "将真钞元素替换为游戏内虚拟金币或抽象金色光芒特效",
    "修改字幕，弱化绝对化回报表达"
  ],
  "human_required": false
}
```

- 依据 `human_required` 字段，系统决定是自动回滚重跑，还是直接挂起并抛入人工异常队列。

## 五、 工程落地与上线防线



### 5.1 Token 熔断与多级模型策略

- **金字塔模型调用：** 基础清洗、格式校验、常规文案等劳动密集型节点采用轻量快捷且成本极低的轻量模型；关键的“合规反思审查（Reviewer）”和“多模态机审（VLM）”才调用顶级大模型。
- **生命周期超时（TTL）熔断：** 针对图结构工作流设置最大循环上限（如重写最多 3 次）。若 3 次后仍未通过合规审计，强制触发熔断，转为人工介入，防止模型因死循环导致 Token 费用爆炸。



### 5.2 异步渲染架构

视频流渲染（如图生视频、视频拼接）属于高耗时、高算力的阻塞型任务。

- **基础架构：** 采用 **FastAPI + Celery + Redis/RabbitMQ** 的异步任务队列架构。
- **逻辑解耦：** 前端文本和脚本生成完毕后，立即向渲染队列发送异步 Job 锁并释放连接，渲染服务器按队列优先级平稳消化，规避后端服务超时断连或高并发崩溃。



### 5.3 多语言（Localization）与字体兼容

- **字体防塌陷：** 针对非拉丁语系（印地语、阿拉伯语等），必须在视频渲染底片（如 Python Pillow/OpenCV 或 FFmpeg 节点）中提前硬编码挂载支持该语系的高质量开源字体（如 `Google Noto Fonts`），彻底根绝因字体缺失导致的乱码方块（口口口）现象。
- **音频-画面自适应动态拉伸：** 针对不同语种（例如德语、印地语通常比英语长 20%-30%）导致的口白时长变动，分镜留白时间（Duration）必须通过代码读取 TTS 产生的实际音频长度进行自适应弹性拉伸，防止“话未完、画已切”的画面脱节。



### 5.4 人机协同（Human-in-the-Loop）防线

在系统上线初期，切忌追求 100% 全无人闭环。系统设置两个“人工控制闸口”：

1. **脚本闸口：** 脚本 JSON 生成且通过初审后，人工在看板上确认一键 Approve。
2. **成片闸口：** 视频完全渲染拼接完毕后，正式上架广告账户前，人工进行最终审查。通过数据沉淀和 Skill 模型的调优，逐步放开全自动比例。



### 5.5 规避 Meta 素材相似度风控（感知哈希对抗）

如果针对同类工单批量高产，基础底图、LoRA 过于单一会触发 Meta Ads Integrity 系统的感知哈希算法（Perceptual Hashing），被判定为“批量垃圾营销”或“恶意规避系统”从而导致封号。

- **对抗策略：** 在提示词生成器（Prompt Generator）阶段引入**“视觉风格多样化（Style Diversity）随机因子”**。强制工单在“赛博朋克、写实生活、霓虹幻彩、高档商务”等多种截然不同的视觉主调间自动切换，确保高产的同时，素材包在 Meta 眼中呈现出健康、独立的多元状态。

## 六、 总结与 MVP 实施路线

为了推进本项目落地，建议采取“先垂直做深，再水平扩展”的 MVP 策略：

1. **阶段一（单点跑通）：** 固定以 `GAJA777`（印度、首充）为样本，编写死循环脚本，把“工单 -> 结构化 JSON 脚本 -> 手机 UI 透视合成 -> 视频拼接”的最小可行性链路闭环手动跑通。
2. **阶段二（多 Agent 与审核上线）：** 引入 LangGraph 框架，将手动步骤解耦为 Agent 节点，重点攻克基于 VLM 的“合规审计 Skill”和反思重试路由。
3. **阶段三（多工单与数据库挂载）：** 将系统接入网关与 PostgreSQL 数据库，实现 LoRA、地区约束与工单的动态绑定，完成“AI 广告视频工厂”的规模化上线。
