# 广告数据分析素材下载与视频关键帧可靠性设计

**状态：** 已确认，进入实现

## 目标

提高外部 Facebook 投放数据分析任务对图片、视频素材 URL 的下载稳定性；视频素材在完成画面分析前必须取得首帧和尾帧，中间帧按画面变化动态选择。

本次不改变外部请求和查询接口：

```text
POST /api/v1/integrations/ad-performance/analysis-jobs
GET  /api/v1/integrations/ad-performance/analysis-jobs/{analysis_id}
```

`external_request_id` 幂等规则、分析结果主结构以及图片/视频生成接口均保持不变。

## 现状与根因

当前媒体下载使用统一 20 秒总时限且不重试。实际验证中，Worker 已获得素材服务器的 HTTP 200 响应，但 HTTPS/TLS 读取偶发变慢，导致下载在 20 秒总时限内被取消。任务会正确降级而不会失败，但 `media_analysis` 无法分析画面。

同一个 Worker 对相同 MP4 单独处理时已验证：可下载、可由 ffprobe 识别，并可由 FFmpeg 抽取关键帧。因此问题是下载链路的瞬时网络容错，不是视频格式、时长、文件大小或 FFmpeg 能力。

## 下载策略

### 分类超时

| 素材 | 单次总下载时限 | 自动重试 | 最长等待（极端） |
| --- | ---: | ---: | ---: |
| 单张图片 | 30 秒 | 1 次 | 约 61 秒 |
| 轮播图 | 每张 30 秒 | 每张 1 次 | 每张独立 |
| 视频 | 80 秒 | 1 次 | 约 161 秒 |

两次尝试之间等待 1 秒。该等待发生在 Celery 异步分析 Worker 中，不阻塞调用方提交任务；调用方继续按现有 GET 接口轮询即可。

### 可重试和不可重试错误

只对短暂性错误重试：

- 连接或读取超时、TLS 读取中断、临时传输错误；
- HTTP 408、429、500、502、503、504。

以下确定性错误不重试：

- URL 非完整 HTTP/HTTPS 地址；
- DNS 解析到内网、回环、链路本地、保留地址等 SSRF 风险目标；
- HTTP 400、401、403、404；
- 空文件、超出大小限制；
- 不支持的图片/视频格式；
- 视频超出时长限制。

安全限制保持不变：视频最大 100 MB、最长 20 秒、仅 MP4/MOV/WebM；所有重定向目标继续重新做公网 DNS 校验。

## 视频帧策略

### 强制首帧和尾帧

视频下载和格式校验成功后，优先抽取：

```text
first_frame.jpg  开场最早可稳定解码画面（通常约 0.1 秒）
last_frame.jpg   结尾最近可稳定解码画面（通常为 duration - 0.1 秒）
```

不强行取精确 0 秒和精确结束时间，避免部分 H.264/MP4 容器在边界无法独立解码。它们仍代表视频开场和结尾画面。

### 动态中间帧

系统按视频时长生成有限的中段候选帧，使用低分辨率灰度图的像素差异过滤重复画面：

- 首帧与尾帧始终保留；
- 只保留与首尾帧、已保留中间帧有明显画面差异的候选；
- 最多保留 3 张中间帧；
- 画面基本静止的视频可只保留首帧和尾帧；
- 画面变化丰富的视频可保留首帧、中间 1～3 帧、尾帧。

发送给大模型的顺序恒定为：首帧、已筛选中间帧、尾帧。

## 结果与降级规则

内部 `media_summary` 增加非敏感诊断字段：

```json
{
  "download_attempts": 2,
  "download_retry_used": true,
  "first_frame_generated": true,
  "last_frame_generated": true,
  "middle_frame_count": 2,
  "frame_count": 4,
  "video_visual_complete": true
}
```

规则：

1. 下载成功且首帧、尾帧均成功：`video_visual_complete=true`，允许模型输出完整视频画面建议。
2. 首帧、尾帧成功但没有中间帧：仍为完整视频画面分析；中间变化有限不构成降级。
3. 下载成功但任一首尾帧失败：分析任务仍成功，媒体状态为部分可用，`video_visual_complete=false`，结果明确提示视频画面不完整，不能输出假装完整的画面结论。
4. 两次下载均失败：分析任务仍成功；投放指标、文案、定向、公开参考分析照常返回，媒体部分明确降级原因。

Worker 日志记录素材主机、尝试次数、成功或失败类别；对外结果不暴露 Worker 本地文件路径。

## 验证标准

1. 单元测试证明：短暂下载错误会重试一次，确定性错误不会重试，部分文件会被清理。
2. 单元测试证明：视频结果必须同时含 `first_frame.jpg` 和 `last_frame.jpg` 才是完整可用；中间帧数量为 0～3 且随画面差异变化。
3. Docker 重建后，使用已验证的 MP4 URL 执行完整异步任务：下载成功、ffprobe 成功、首帧和尾帧成功、最终 `media_analysis` 不降级。
