# 广告研究视觉评分重构设计

**日期：** 2026-07-23
**状态：** 设计已确认，待实施计划
**适用首期场景：** `country=IN`、`category=gambling`、`target_count=25`
**与既有设计的关系：** 本文覆盖并修正《广告研究引擎设计》中“技术合格后的模型分类与排序”和“媒体处理”部分；异步任务、`external_user_id` 幂等、Celery/Redis、外部轮询、24 小时结果保留及 `athm793/meta-ads-scraper` 采集器集成维持不变。

## 1. 背景与问题

已完成的一次真实任务（`IN + gambling`、目标 25 条、无外部关键词）经历四轮采集后，漏斗数据为：

| 阶段 | 数量 | 说明 |
| --- | ---: | --- |
| 原始采集 | 385 | Collector 召回的公开广告 |
| 去重后 | 341 | 按广告 ID 去重 |
| 技术合格 | 39 | 主要因超过 30 秒、时长无法探测或投放不足 1 天被淘汰 |
| 模型相关 | 0 | 39 次模型调用成功，但均被当前硬条件排除 |
| 最终保留 | 0 | 任务以 `insufficient` 完成 |

当前问题不是模型网关故障，而是两类规则过严：

1. 媒体环节把“没有原始封面”“一次 `ffprobe` 失败”等可恢复问题直接当作最终淘汰；并且逐条串行探测时长，导致整体任务很慢。
2. 模型输出中的 `recommendation`、`category_match`、`is_obviously_unrelated`、`category_confidence >= 0.85` 同时作为硬门槛。它们重叠且让模型的一次保守判断成为一票否决。

业务目标是研究其他投放方公开可见的博彩创意，而不是基于广告文字做合规或业务性质裁决。首期最重要的信号是**短视频画面是否包含博彩元素或明显博彩风格**；标题、正文、CTA、广告主名称与落地页不参与该视觉评分。

## 2. 目标、非目标和边界

### 2.1 目标

- 保留媒体技术合格的公开短视频广告，针对每条广告产生可比较的 0–100 分，而不是让模型直接“保留/排除”。
- 以视频关键帧和可用封面为输入，优先识别直接博彩元素，也识别金币、水晶、`WIN`、`VIP`、奖励、倍率、爆奖等博彩风格 UI/特效。
- 最终按分数排序返回前 25 条；只要技术合格且已评分，就进入排名池。
- 当首轮质量不足时，利用高分广告的**可见视觉元素**反馈下一轮关键词规划，提高召回；不把博彩词典写死到后台业务逻辑。
- 在保持 `ACTIVE`、视频时长不超过 30 秒、投放至少 1 天等产品约束的前提下，提高技术合格率和吞吐量。

### 2.2 非目标

- 不推断真实花费、CPA、ROAS、收入、转化或盈利能力。
- 不访问广告落地页，不模拟审核员或真实用户，不验证、复现或确认 Cloaking。
- 不因正文、标题、CTA、广告主页名称或域名判断博彩相关性；这些字段可以在最终结果中展示，但视觉评分权重为 0。
- 不保证“所有高分广告都是真金博彩”；评分含义是公开视频素材呈现的博彩元素/风格强度。

## 3. 总体流程

```text
模型规划检索词
  → Collector 召回公开广告
  → 按广告 ID 去重
  → 并发媒体准备与技术可用性确认
  → 抽取视频代表帧
  → GPT-5.4 mini 多模态视觉评分
  → 后台确定性加分与排序
  → Top 25 / 判断是否补采
  → 外部系统轮询读取结果（24 小时内）
```

`athm793/meta-ads-scraper` 仍是第一期 Collector。它只负责按国家和 query 召回公开广告；媒体可靠性、时长、关键帧、评分、补采和排名均由本系统负责，采集器实现可替换。

## 4. 技术可用性：只保留可验证的产品硬条件

每条候选必须满足下列最终条件才能进入模型评分池：

- `ACTIVE`；
- 存在可安全取得的视频源；
- `days_running >= 1`；
- 最终可确认视频时长，且 `duration_seconds <= 30`；
- 广告 ID 未重复；
- 至少得到一张可供模型分析的图像：原始封面或从视频自动生成的帧。

封面不是独立的硬淘汰项：原始 `thumbnail_url` 不存在、过期或下载失败时，系统必须优先从已可访问的视频生成封面/代表帧。只有视频本身不可用，或无法产生任何可分析帧，才以明确原因码淘汰。

### 4.1 时长确认顺序

为避免一次网络波动造成误淘汰，时长按以下优先级取得：

1. 使用 Collector 已提供且格式合法的时长；
2. 对远程视频 URL 使用 `ffprobe`；
3. 远程探测失败时按退避策略重试两次；
4. 仍失败时，在大小、类型和超时受控的条件下临时下载视频，调用本地 `ffprobe`；
5. 仍无法确认时，以 `duration_unavailable` 淘汰。

`duration_over_30` 仅在确认时长大于 30 秒后产生。探测尝试、最终来源和失败原因必须写入任务诊断，便于区分“视频过长”和“媒体/网络不可用”。

### 4.2 并发与临时文件

媒体准备不得逐条串行运行。建议新增：

```env
AD_RESEARCH_MEDIA_CONCURRENCY=6
AD_RESEARCH_FRAME_CONCURRENCY=4
```

- `AD_RESEARCH_MEDIA_CONCURRENCY` 限制下载、远程探测、重试和本地 `ffprobe` 的并发总量；
- `AD_RESEARCH_FRAME_CONCURRENCY` 限制视频解码和关键帧导出，避免 Worker 内存/CPU 被高分辨率视频抢占；
- 任务取消、失败、过期或完成后，立即清除无须返回的临时下载文件；最终封面和证据帧可随任务结果保留至 24 小时到期。

现有全局控制保持：

```env
AD_RESEARCH_WORKER_CONCURRENCY=2
AD_RESEARCH_MODEL_CONCURRENCY=6
```

## 5. 关键帧与封面策略

### 5.1 默认帧

对每个技术合格视频，按已确认时长在 20%、50%、80% 位置提取三张代表帧；可用原始封面或第一张可读代表帧作为展示封面。

### 5.2 低置信度补帧

第一轮模型结果若 `analysis_confidence < 0.60`，再在 35%、65% 提取两张帧，并对同一候选进行一次补充视觉评分。单条视频最多向模型提供五张视频帧，避免无限增加延迟和成本。

### 5.3 失败处理

帧提取应遵循受控重试；单帧失败不立即淘汰其余有效帧。若至少有一张可分析图像，广告继续评分；若所有帧与封面都无法生成，记录 `no_analyzable_visual` 并淘汰。

## 6. GPT-5.4 mini 视觉评分契约

### 6.1 调用原则

模型使用 `gpt-5.4-mini`，并固定：

```json
{"reasoning_effort":"none"}
```

模型输入只包含：

- 视频关键帧（3 张，低置信度时最多补到 5 张）；
- 可选原始封面或自动生成封面；
- 视频时长、投放天数、帧数量等非文本媒体元数据；
- 本次研究的自由文本类别（例如 `gambling`）。

模型输入**不得包含**广告标题、正文、CTA、广告主名称、主页名称、落地页 URL 或域名。这样即使广告文案采用规避写法或完全不写博彩文字，也不会降低视觉评分。

### 6.2 模型结构化输出

模型每次成功分析都必须返回以下 JSON；每个字段均是分数或可核验的视觉证据，不输出“保留/排除”结论：

```json
{
  "core_gambling_points": 0,
  "reward_ui_points": 0,
  "gambling_style_points": 0,
  "casino_context_points": 0,
  "media_quality_points": 0,
  "analysis_confidence": 0.0,
  "visible_elements": [],
  "visual_evidence": [
    {
      "frame_index": 1,
      "description": "可见元素与画面位置的简要说明"
    }
  ],
  "uncertain": false
}
```

字段范围与解释：

| 字段 | 范围 | 视觉依据示例 |
| --- | ---: | --- |
| `core_gambling_points` | 0–40 | 老虎机/777、轮盘、扑克或牌桌、真人荷官、骰子、Aviator/Crash、捕鱼博彩界面、下注/赔率/余额等直接赌博玩法 UI |
| `reward_ui_points` | 0–20 | 金币、现金雨、水晶、奖励宝箱、Jackpot、Bonus、倍数、爆奖、领取奖励、`WIN`、`VIP` 等奖励/获胜 UI 或特效 |
| `gambling_style_points` | 0–15 | 高饱和霓虹赌场视觉、夸张中奖动画、筹码/金币环绕、转盘/抽奖式游戏大厅风格 |
| `casino_context_points` | 0–10 | 赌场场景、发牌/荷官、投注面板、游戏大厅、明显真钱游戏氛围 |
| `media_quality_points` | 0–5 | 主体清晰、帧覆盖足够、画面可辨，不能因“制作精良”替代博彩元素 |
| `analysis_confidence` | 0–1 | 模型对可见画面判断的把握程度 |

模型应基于实际帧内容给分，不得根据不可见的文字文案、未提供的声音、广告主或 URL 臆测。`uncertain=true` 仅表达视觉不确定性，不能使候选自动出局。

### 6.3 移除的硬淘汰依赖

最终选择逻辑不再依赖、也不再要求模型输出：

```text
recommendation
category_match
is_obviously_unrelated
category_confidence
```

其中 `category_match` 与 `is_obviously_unrelated` 在当前场景语义重叠；`recommendation` 更不应覆盖可见视觉证据。若为兼容历史模型记录暂时保留旧字段，它们仅能记录，不得参与新排序、淘汰或补采停止判断。

## 7. 后台确定性总分与排序

后台不使用博彩文字词典做硬规则，只对模型输出和公开投放持续信号进行确定性汇总：

```text
visual_total =
    core_gambling_points
  + reward_ui_points
  + gambling_style_points
  + casino_context_points
  + media_quality_points

public_continuity_points = min(10, 根据 active_days 计算的公开持续投放代理分)
final_score = min(100, visual_total + public_continuity_points)
```

`public_continuity_points` 的精确分段在实施计划中定义并单元测试；它只能作为同等视觉强度候选的轻量排序信号，不能推断投放成本或真实效果。

排序键依次为：

1. `final_score` 降序；
2. `visual_total` 降序；
3. `active_days` 降序；
4. 可分析帧数量与媒体质量降序；
5. 稳定的广告 ID 升序，确保结果可复现。

所有技术合格且模型评分成功的广告都进入排序池。模型调用失败的广告记录为 `model_scoring_failed`，不会被伪造分数；它们可在一次受控重试后仍失败时留在未评分统计中，而不是与低分广告混排。

## 8. Top 25、补采和关键词反馈

### 8.1 返回规则

- 当评分池至少有 25 条时，始终返回排序前 25 条；不再设置模型相关性淘汰阈值。
- 第 25 名分数低于 55 分时，可继续补采以提升结果质量；55 分是“是否继续找更好素材”的内部触发线，**不是**单条广告的排除阈值。
- 达到最大 4 轮、500 条原始候选，或一轮没有新增去重候选时停止。
- 停止时若评分池不少于 25，返回前 25 条，状态为 `completed`，即使其中有低分；少于 25 时返回实际条数，状态为 `insufficient`，同时返回漏斗统计和不足原因。

### 8.2 动态关键词规划

模型仍可根据国家、类别、外部种子词、已用 query、每轮召回/去重/技术淘汰统计以及**已获高分候选的 `visible_elements`**规划下一轮检索词。

关键词规划是增加召回的策略，不改变后台技术规则：

- 采用多组受控 query，优先“玩法/视觉元素 + 转化/奖励语境”的组合；
- 可以提出拼写变体、Emoji 与本地语言词，但必须由模型返回受控 JSON，并由后台去重、限量和审计；
- 下一轮优先扩展高分视频已显示的玩法、界面和奖励风格，而不是将某个内部投手习惯（例如特定神话人物或内部品牌词）写成固定规则；
- 若无高分样本，模型根据本轮噪声/缺口调整 query；系统保留每轮 query、原因和漏斗统计供复盘。

## 9. 外部轮询结果与保留

外部请求、`external_user_id` 幂等、异步状态机和轮询 URL 保持既有契约。完成结果中每条广告至少应包含：

```json
{
  "ad_id": "...",
  "video_url": "...",
  "thumbnail_url": "...",
  "duration_seconds": 0,
  "active_days": 0,
  "final_score": 0,
  "visual_total": 0,
  "public_continuity_points": 0,
  "analysis_confidence": 0.0,
  "visible_elements": [],
  "visual_evidence": [],
  "media": {
    "cover_source": "original_thumbnail|generated_frame",
    "frame_count": 3,
    "duration_source": "collector|remote_ffprobe|downloaded_ffprobe"
  }
}
```

广告原始文案可作为展示字段返回，但明确标记为 `display_only`，不作为评分证据。任务结果、最终封面和证据帧自完成起保留 24 小时；外部系统在有效期内可重复轮询读取。到期后清理媒体和完整结果，并返回既有的 `410 Gone` 语义。

## 10. 可观测性与诊断

每轮及整个任务应记录并返回不含敏感载荷的汇总：

- `raw_collected`、`deduplicated`、`technical_qualified`、`model_scored`、`selected_count`；
- 技术淘汰原因计数：`status_not_active`、`missing_video`、`active_days_below_minimum`、`duration_unavailable`、`duration_over_30`、`no_analyzable_visual` 等；
- 时长来源、探测重试次数、封面来源和帧提取失败数；
- 模型调用次数、低置信度补帧次数、模型重试次数、评分分布和第 25 名分数；
- 补采触发原因、每轮 query 数量、重复 query 拒绝数、停止原因和总耗时。

日志只记录任务 ID、广告 ID、受控错误码和聚合统计；不输出模型密钥、完整外部凭据或不必要的媒体二进制内容。

## 11. 验收标准

### 11.1 自动化验证

- 原始封面缺失但视频可用时，能生成封面并进入评分；
- 远程 `ffprobe` 的瞬时失败会重试，并能退回到临时下载后的本地探测；
- 媒体处理并发受配置限制，不再按候选串行执行；
- 对 20%、50%、80% 帧评分；低置信度时只补 35%、65%，上限五帧；
- 模型提示中不含标题、正文、CTA、广告主和 URL；
- 任意有效模型 JSON 都能映射为 0–100 的确定性分数；旧 `recommendation` 或类别布尔字段不会改变排序结果；
- 25 条以上评分候选时，返回恰好 25 条且按排序键稳定；少于 25 时保留已评分候选并正确标记 `insufficient`；
- 24 小时清理后结果与媒体不再可用，任务轮询语义保持一致。

### 11.2 真实回归验证

使用单个 `IN + gambling` 异步任务做受控真实验证，保留同一 `external_user_id`、`task_id`、完整漏斗统计、耗时和最终分数分布。验收时至少比较：

- 技术合格数与历史基线 39 条的变化；
- 已评分数、返回数、Top 25 第 25 名分数；
- 时长探测总耗时及 `duration_unavailable` 数量；
- 自动生成封面/帧对原始封面缺失候选的挽回数；
- 随机人工复核 Top 25 中视频画面是否具有直接博彩元素或博彩风格。

真实验证不以“推断广告真实营收”或“验证落地页规避行为”为验收条件。

## 12. 实施顺序

1. 盘点现有媒体与模型模块，补充数据结构、配置和测试夹具；
2. 改造并发时长/封面/关键帧准备链路及其重试、清理和诊断；
3. 替换模型视觉评分契约、提示构造和结构化解析；
4. 实现确定性评分、排序、补采触发和关键词反馈；
5. 更新任务结果、进度、指标和 API 测试；
6. 完成单元/集成测试后进行一次受控真实 `IN + gambling` 回归测试，出具数据报告。
