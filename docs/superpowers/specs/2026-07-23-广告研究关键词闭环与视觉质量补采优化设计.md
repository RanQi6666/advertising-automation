# 广告研究关键词闭环与视觉质量补采优化设计

**日期：** 2026-07-23
**状态：** 已确认，进入实施计划
**适用首期场景：** `country=IN`、`category=gambling`、`target_count=25`
**基线版本：** `874526004bbb83ec81425ef3559166d64ac6376f`

## 1. 背景与目标

现有广告研究链路已经可以通过 `athm793/meta-ads-scraper` 从公开 Meta Ad Library 召回广告，完成短视频媒体检查、并发抽帧、GPT-5.4 mini 纯视觉评分和 Top-N 返回。真实测试已经证明，技术链路可以获得足够的短视频候选，但最终 Top 25 中仍混入较多普通板球、Telegram 预测、交易喊单和其他博彩相邻内容。

本次优化的目标不是把国家、博彩词或玩法词写死在后台，而是让模型基于真实每轮召回质量持续调整关键词，并用严格的纯视觉优先级将“游戏画面中带博彩元素”的素材排在最前面。

首期成功定义：

1. 对于 `target_count=25`，成功任务一定返回且只返回 25 条技术合格、模型已完成视觉评分的广告；
2. P1 游戏化博彩优先于 P2 明确体育博彩，P2 优先于 P3 博彩相邻，P3 优先于 P4 低相关补位；
3. 不再因文字、标题、CTA、广告主或投放天数影响视觉模型的博彩判断；
4. 系统在公开广告资料边界内工作：不访问或模拟落地页用户路径，不复现审核规避或 Cloaking，不推断实际花费、CPA、ROAS 或真实转化。

## 2. 不变边界与外部契约

### 2.1 采集实现和公开资料边界

首期继续使用 `athm793/meta-ads-scraper` 作为 Meta Ad Library Collector，并通过项目内部的 `meta_ads_collector` Bridge 调用。Collector 只负责按查询词和国家召回公开广告及公开媒体地址；它不参与业务分类、最终排序或结果存储。

系统只使用公开广告库字段、公开视频、公开缩略图和系统从公开视频生成的封面/关键帧。广告快照链接仅作为外部查看入口，不做落地页跟随、IP/设备指纹差异探测或任何真实用户模拟。

### 2.2 外部请求和轮询

对外接口保持不变：

```text
POST /api/v1/integrations/ad-research/jobs
GET  /api/v1/integrations/ad-research/jobs/{task_id}
```

请求仍使用 `external_user_id` 作为一次逻辑请求的幂等键。外部系统提供：国家、类别、可选种子关键词和目标数量；关键词规划、质量补采、视觉分类、补位和内部阈值全部由后台处理。

`target_count` 继续保留为兼容字段，范围保持 1 至 25。成功任务必须精确返回请求的数量；当前生产业务固定请求 25，因此：

```text
status=completed  =>  ads.length=25
```

结果保留 24 小时，外部系统轮询读取，不需要 callback 或“已获取结果”确认。

### 2.3 成功、失败与旧状态兼容

新任务只产生下列终态：

```text
completed
failed
expired
```

- `completed`：有精确数量的技术合格且模型评分成功广告；
- `failed`：Collector、媒体、模型或预算耗尽后仍无法得到精确数量的**已评分技术合格**广告；不返回部分成功结果；
- `expired`：完成结果 24 小时后已删除。

不再为新任务产生 `insufficient`。轮询和清理逻辑仍可读取、清理历史 `insufficient` 记录，避免旧任务在升级后变成不可访问数据。

## 3. 技术合格候选

最终广告必须全部满足以下技术事实：

- Meta 广告状态为 ACTIVE；
- 有可访问、可下载的视频；
- 最终探测的视频时长 `<= 30s`；
- 公开可见投放时间 `>= 1` 天；
- `ad_library_id` 去重；
- 有可分析视觉资料：原始缩略图可用，或从下载视频生成封面和关键帧；
- 已由视觉模型返回结构化、可校验的评分。

原始封面缺失不是淘汰理由：系统应下载视频、生成封面后继续。时长探测失败必须按既有下载/本地 `ffprobe` 路径和重试配置尝试，所有路径均失败后才记录 `duration_unavailable` 并淘汰。

现有并发媒体检查、短视频优先探测、并发下载和 20%/50%/80% 抽帧策略继续保留。模型置信度低于 `0.60` 时，额外生成 35% 与 65% 两帧并重新评分；最多五帧。补帧失败不使原本技术合格素材失效。

## 4. 结构化关键词闭环

### 4.1 查询计划结构

关键词模型不再只返回字符串数组，而是返回可验证的查询计划：

```json
{
  "round_review": {
    "winning_query_families": ["..."],
    "low_yield_query_families": ["..."],
    "false_positive_patterns": ["..."],
    "missing_game_families": ["..."],
    "strategy_summary": "..."
  },
  "queries": [
    {
      "query_id": "r1_q01",
      "query": "slot jackpot bonus",
      "intent": "game_gambling",
      "locale": "en-IN",
      "expected_visuals": ["slot reels", "jackpot UI", "coin win effects"],
      "reason": "寻找游戏化老虎机短视频"
    }
  ]
}
```

`intent` 只能是：

```text
game_gambling
sports_betting
local_exploration
format_exploration
```

模型在首轮依据国家、类别和外部种子词规划。后续轮把上一轮的汇总复盘与新查询规划合并到**同一次**模型调用，不增加额外模型请求。

### 4.2 防漂移约束

模型不能直接把偶然 OCR 文字、普通人物名、频道名、按钮文字或普通比分作为下一轮检索词。例如不得仅因某帧出现就生成 `continue button`、`entertainment only`、`join with us` 或普通比赛球队名。

每个新增查询必须提供：

- 来源：外部种子、上一轮高分视觉集群或缺失玩法；
- 业务含义：为什么是博彩游戏或明确体育博彩相关；
- 预期视觉：期望召回的游戏 UI、下注 UI 或多信号画面；
- 原因：为什么该查询比被暂停的查询更可能提高 P1/P2 占比。

后台不维护印度博彩词库。查询意图、国家本地化词、变体词和探索方向由 GPT-5.4 mini 在受控 JSON 合同中生成；后台只做 schema 校验、长度限制、跨轮去重和预算控制。

### 4.3 查询归因和统计

每条广告要记录首次及全部来源查询：

```json
{
  "first_source_query_id": "r1_q01",
  "source_query_ids": ["r1_q01", "r2_q03"]
}
```

相同 `ad_library_id` 只进行一次媒体处理和一次最终视觉评分，但允许关联到多个查询。每个查询、每轮和整个任务至少统计：

```text
raw_collected
new_unique_count
duplicate_count
duration_le_30_count
technical_qualified
model_scored
game_gambling_count
sports_betting_count
gambling_adjacent_count
unrelated_count
score_above_55
average_visual_score
best_visual_score
```

模型在下一轮针对每个查询建议 `expand`、`refine`、`pause`、`drop` 或 `explore_related`。这些建议作为可观测诊断返回到任务摘要，原始模型 prompt 和完整响应不对外返回。

## 5. 纯视觉评分和优先级

### 5.1 模型输入边界

GPT-5.4 mini 的视觉评分只接收：

- 类别；
- 技术阶段确认的真实视频时长；
- 封面和关键帧；
- 帧数。

模型不得接收或使用：标题、正文、CTA、广告主、主页、落地页 URL、来源关键词、广告投放天数、公开持续投放分数。

模型调用固定：

```json
{
  "model": "gpt-5.4-mini",
  "reasoning": {"effort": "none"}
}
```

### 5.2 视觉输出合同

模型返回固定 JSON，后台裁剪、校验并计算总分：

```json
{
  "visual_priority": "game_gambling",
  "gameplay_gambling_points": 30,
  "multi_signal_style_points": 18,
  "betting_mechanism_points": 12,
  "gambling_visual_style_points": 8,
  "visual_clarity_points": 9,
  "media_quality_points": 5,
  "visual_total": 82,
  "analysis_confidence": 0.92,
  "gambling_signals": ["coins", "WIN", "VIP"],
  "game_visual_present": true,
  "visual_evidence": [{"frame_index": 1, "detail": "..."}],
  "retrieval_hints": ["..."],
  "uncertain": false
}
```

分项上限：

| 维度 | 上限 |
| --- | ---: |
| 游戏化博彩玩法 | 40 |
| 游戏画面中的多博彩信号 | 20 |
| 下注与交易机制 | 15 |
| 博彩整体视觉风格 | 10 |
| 视觉清晰度 | 10 |
| 媒体质量 | 5 |

`visual_total` 必须由后台按六项相加得到，模型提供的总分不被直接信任。

### 5.3 优先级定义

**P1：`game_gambling`**

以下任一类直接进入 P1：老虎机、777、轮盘、牌桌、真人荷官、Aviator/Crash、捕鱼、Teen Patti、Rummy、明确下注/派彩/余额/钱包 UI。

如果是一般游戏画面，必须同时具备“清晰游戏画面”和至少两种博彩风格信号才可进入 P1。信号包括：金币、WIN、VIP、Bonus、水晶、Jackpot、倍率、爆奖动画、钱包、余额、转盘、奖金等。孤立的一个金币、VIP、WIN 或 Bonus 不足以进入 P1。

**P2：`sports_betting`**

必须同时展示体育比赛和明确的赔率、下注按钮、投注金额、钱包、余额或结算机制。普通比赛、比分、板球新闻、赛事预测和 Telegram 频道不能进入 P2。

**P3：`gambling_adjacent`**

具有博彩相邻视觉或证据不足的候选，不能满足 P1/P2 标准。

**P4：`unrelated`**

技术合格、已经完成模型评分但没有足够博彩视觉证据的候选。P4 只允许在保障精确返回数量时补位。

### 5.4 排序

最终主分：

```text
final_score = visual_total
```

不再把 `public_continuity_points` 加入主分。它和 `active_days` 继续保留在结果中，仅作同层级、同分附近的稳定排序参考，不能补偿弱视觉相关性。

稳定排序：

```text
visual_priority(P1 > P2 > P3 > P4)
→ visual_total
→ analysis_confidence
→ active_days
→ frame_count
→ ad_library_id
```

## 6. 质量补采与精确返回数量

### 6.1 轮次和预算

采用四轮标准采集和两轮定向补采：

```text
标准轮次：1 至 4
定向质量补采：5 至 6
最大轮次：6
最大原始候选：650
单查询最多采集：50
```

在每轮完成后，系统先聚合全部历史候选，再执行去重、技术检查、模型评分和优先级统计。结束条件按顺序判断：

1. P1 数量达到目标数量：立即完成；
2. 达到第 4 轮且 P1 不足：依据查询级产出选择性进入第 5、6 轮，优先补缺失玩法和高产出 P1 视觉集群；
3. 第 6 轮或原始候选预算耗尽：若已拥有目标数量的技术合格且模型已评分广告，进入 P4 透明补位后完成；
4. 第 6 轮或预算耗尽仍不足目标数量的技术合格且模型已评分广告：失败，不返回部分成功；
5. Collector、媒体或模型发生不可恢复全局故障：失败。

任何候选模型请求失败后应进行一次受限重试；仍失败的候选不参与补位。只有全局评分服务不可恢复或预算耗尽导致无法形成目标数量时才失败。

### 6.2 最终填充

在所有已评分技术合格候选中，严格按 P1 → P2 → P3 → P4 取前 `target_count` 条。

当 P1～P3 不足时，P4 用于保证数量，并必须显式标注：

```json
{
  "is_fallback": true,
  "fallback_reason": "insufficient_high_relevance_candidates"
}
```

P1～P3 的 `is_fallback=false`。任务摘要返回：

```json
{
  "quality_summary": {
    "game_gambling_count": 12,
    "sports_betting_count": 6,
    "gambling_adjacent_count": 4,
    "fallback_count": 3,
    "fallback_used": true
  }
}
```

这满足“成功必返 25 条”的外部要求，同时不把补位素材伪装成高相关博彩广告。

## 7. 数据保留、性能与可观测性

- 最终结果和被选中广告的封面/关键帧最多保留 24 小时；
- 未选中候选的媒体在最终排序后删除；
- 任务摘要、查询级汇总、技术淘汰计数和脱敏错误摘要可保留 30 天；
- 不长期保存原始候选完整媒体、完整模型输入、模型原始响应、临时 CDN 下载链接或任何密钥。

并发保持：

```env
AD_RESEARCH_WORKER_CONCURRENCY=2
AD_RESEARCH_MODEL_CONCURRENCY=6
```

其中模型并发继续使用 Redis 分布式租约保证全局上限六。媒体探测和抽帧继续由独立并发配置控制，避免逐条串行 `ffprobe`。

轮询进度新增：当前轮、各优先级计数、技术合格数量、模型评分数量、已选数量、查询级摘要和补位数量。对外不暴露内部临时路径、模型提示词、密钥或完整错误栈。

## 8. 兼容性、迁移和验收

本次不新增数据库表，也不改变创建任务请求体。任务 `summary_json` 和 `result_json` 增加字段，属于向后兼容扩展；已有调用方可以继续读取原字段。

必须更新并通过的验收：

1. 成功的 `target_count=25` 任务精确返回 25 条；
2. P1 始终优先于 P2/P3/P4，即使 P2 的视觉分更高；
3. P2 必须同时有比赛和明确下注机制，普通板球不能误入 P2；
4. 一般游戏只有“游戏画面 + 两种博彩信号”才进入 P1；
5. 标题、正文、CTA、广告主、URL、来源关键词和投放天数不被发送给视觉模型；
6. 相同广告多查询召回后只评分一次，但结果能看到全部来源查询；
7. 后续轮模型利用真实查询统计复盘，且不会用偶然 OCR 或普通频道文字漂移；
8. 当 P1～P3 不足但总已评分技术候选足够时，返回 25 条并准确标记 P4 补位；
9. 当总已评分技术候选不足 25 条时，任务失败且不返回部分结果；
10. 结果在 24 小时内可轮询，过期清理后返回 410；
11. 现有公开广告研究边界、Celery Worker、Redis 队列和模型全局限流不被破坏。
