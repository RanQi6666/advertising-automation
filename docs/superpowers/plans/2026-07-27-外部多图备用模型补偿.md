# 外部多图备用模型补偿 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Preserve successful images in an external multi-image job and generate only failed slots through the next priority fallback provider.

**Architecture:** Keep one `GenerationTask` and its public `job_id`. Persist slot status and successful image dictionaries in the existing JSON `result`; retries rebuild briefs only for slots without a success. The existing retry lifecycle advances priority-route metadata after a technical failure, then the next provider receives only pending slots.

**Tech Stack:** FastAPI, Pydantic, SQLAlchemy async sessions, Celery, Redis, pytest, pytest-asyncio.

## Global Constraints

- Modify only `advertising-automation`; do not modify `pixel_project`.
- Do not change external create-request fields, task IDs, or polling URLs.
- Keep a terminal partial result at `status=failed`, returning already successful `images`.
- Never regenerate or overwrite a slot that already has a saved successful image.
- Keep `fixed` and `round_robin` behavior unchanged.
- No database migration or backfill is needed; task state remains in existing JSON columns.
