# 外部图片生成「慢 + 直接失败」修复方案

## 背景 / 根因（已用生产日志确认）

- 服务全部正常：`worker_image`、`redis`、`db`、`backend` 都 Up 且 healthy。
- 生产日志实测：`gpt-image-2` 网关单张生成耗时 **107s（HTTP）/ 141s（整任务）**。
  ```
  07:56:51 Task received
  07:58:38 POST https://model.ggcss.xyz/v1/images/generations "HTTP/1.1 200 OK"   ← 约 107s
  07:59:12 Task succeeded in 141.40s
  ```
- 关键问题三条：
  1. `GatewayImageProvider` 的 httpx 超时**写死 120s**，而生成本身就要 107~141s，逼近红线 → 稍慢 / 并发高峰 / `count=2` 就会 `ReadTimeout` → `ProviderError`。
  2. 外部图片任务 `max_attempts=1` → 一次失败即永久 `failed`，不重试。
  3. `GatewayImageProvider.generate_images` **逐张串行**，`count=N` 时长线性叠加，更容易触发超时。

**结论：不是服务坏了，是「模型慢 + 超时太紧 + 不重试 + 串行」。**

## 目标

1. 放宽网关图片 HTTP 超时并做成可配置（默认 300s）。
2. 外部图片任务支持自动重试（默认 3 次），可配置。
3. 网关多图并行生成，缩短 `count>1` 的总时长。
4. 不修改 `.env` / `.env.production`（只在示例文件里记录新配置）。

## 改动清单

### 1. `backend/app/core/config.py` — 新增两个配置项

在 `model_gateway_text_timeout_seconds`（第 38 行附近）后面新增图片超时配置：

```python
    model_gateway_image_timeout_seconds: float = Field(default=300.0, ge=1, le=900)
```

在 `image_queue_concurrency` 附近或任务相关配置区新增外部图片重试次数：

```python
    external_image_generation_max_attempts: int = Field(default=3, ge=1, le=5)
```

> 命名随现有风格；只要 `factory.py` 和 `external_image_generation_service.py` 引用一致即可。

### 2. `backend/app/integrations/image/gateway_provider.py` — 超时可传入 + 多图并行

**(a) `__init__` 支持传入 timeout（默认 300，不再写死 120）：**

当前第 28 行：
```python
        self._http_client = http_client or httpx.AsyncClient(timeout=120.0)
```
改为在 `__init__` 参数里新增 `timeout_seconds: float = 300.0`，并：
```python
        self._http_client = http_client or httpx.AsyncClient(timeout=timeout_seconds)
```

**(b) `generate_images` 由串行改并行：**

当前是 `for brief in briefs:` 顺序 `await`。改为把「单张生成」抽成一个内部 async 方法（例如 `_generate_single(brief)`），再用 `asyncio.gather` 并发：

```python
import asyncio
...
    async def generate_images(self, briefs: list[ImageBrief]) -> list[GeneratedImage]:
        results = await asyncio.gather(*(self._generate_single(brief) for brief in briefs))
        return list(results)

    async def _generate_single(self, brief: ImageBrief) -> GeneratedImage:
        # 原 for 循环体内的逻辑（构造 request、_post_image_generation、解析 url/b64、返回 GeneratedImage）
        ...
```

要求：保持返回顺序与 `briefs` 一致（`asyncio.gather` 默认保序，OK）；异常向上抛出的行为不变。

### 4. `backend/app/services/external_image_generation_service.py` — 用可配置重试

顶部引入 settings（若未引入）：
```python
from backend.app.core.config import get_settings
```
（该文件已在 `execute_task` 里 import 过 `get_settings`，确认后复用即可。）

第 62 行：
```python
            max_attempts=1,
```
改为：
```python
            max_attempts=get_settings().external_image_generation_max_attempts,
```

> 注意：`execute_task` 里「返回图数不足」会抛 `ProviderError`，重试机制要能覆盖这种情况。确认 `GenerationTaskService` 对 `ProviderError` 会走重试（结合 `generation_task_auto_retry_enabled` / `max_attempts`）。若默认不重试 provider 错误，需让 provider 超时/网关 5xx 类错误可重试。

## 给外部对接方的约定（不改代码，但要同步）

- `/api/v1/integrations/image-generation/jobs/{job_id}` 是**异步长任务**，单次生成约 1~3 分钟。
- 轮询建议 **3~5 秒/次**，带退避，别当同步接口等。
- 失败时读取响应 `data.error` 字段定位原因。
