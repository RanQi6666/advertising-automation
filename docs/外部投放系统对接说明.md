# 外部投放系统对接说明

本文档给外部投放系统开发人员使用。当前联调方式为“跳转进入 AI 系统 + token 保护 API + 最终确认后回跳投放系统”。

## 基础信息

```text
AI 系统临时测试地址：
https://atom-crusader-amid.ngrok-free.dev

接口鉴权方式：
Authorization: Bearer <access_token>

也兼容 URL 参数：
?access_token=<access_token>

投放系统接收地址：
https://ads.ggcss.xyz/api/ai/receive_ai_ads
```

说明：

- 页面入口需要带 `access_token`，这样进入 AI 系统后才能继续调用受保护 API。
- `/api/v1/...` 业务接口必须带 token。
- `/api/v1/health/live` 健康检查不需要 token。
- 当前是浏览器跳转回投放系统，不是 AI 后端主动 POST 回调。

## AI 创建入口

外部投放系统点击“AI 创建”时，请打开：

```text
https://atom-crusader-amid.ngrok-free.dev/work-orders/new?access_token=<access_token>
```

AI 系统页面会读取 URL 中的 `access_token`，并在后续 API 请求中自动使用：

```http
Authorization: Bearer <access_token>
```

## 当前联调流程

```text
外部投放系统点击“AI 创建”
-> 跳转到 AI 系统创建工单页，URL 带 access_token
-> 运营在 AI 系统粘贴工单内容
-> AI 系统识别投放参数，人工确认
-> AI 生成选题，人工审核
-> AI 生成文案，人工审核
-> AI 生成图片，人工审核
-> AI 生成视频，人工审核
-> 最终预审
-> 运营点击“确认并回传”
-> 浏览器跳转到投放系统接收地址
```

## 审核任务入口

任务创建后，AI 系统返回的 `review_url` 会自动带 `access_token`：

```text
https://atom-crusader-amid.ngrok-free.dev/review/ad-generation/{job_id}?access_token=<access_token>
```

外部系统或运营人员打开该链接后，可以继续完成审核流程。

## 查询任务

```http
GET https://atom-crusader-amid.ngrok-free.dev/api/v1/integrations/publishing/ad-generation/jobs/{job_id}
Authorization: Bearer <access_token>
```

## 查询最终结果

```http
GET https://atom-crusader-amid.ngrok-free.dev/api/v1/integrations/publishing/ad-generation/jobs/{job_id}/result
Authorization: Bearer <access_token>
```

说明：

- 只有 AI 工单完成最终确认、状态变为 `returned` 后，该接口才返回 200。
- 如果还没有最终确认，会返回 409，表示最终结果还未就绪。
- 如果没有 token 或 token 错误，会返回 401。

## 确认并回传

运营在 AI 系统点击“确认并回传”后，浏览器会跳转到：

```text
https://ads.ggcss.xyz/api/ai/receive_ai_ads
```

跳转时会附带参数：

```text
job_id
status
access_token
external_order_id（如果有）
```

示例：

```text
https://ads.ggcss.xyz/api/ai/receive_ai_ads?job_id={job_id}&status=returned&access_token=<access_token>
```

投放系统收到跳转后，可根据 `job_id` 再调用最终结果接口获取 JSON。

## 需要外部开发确认的问题

1. `campaign_payload` 字段是否够创建广告系列。
2. `adset_payload` 字段是否够创建广告组。
3. `creative_payload` 字段是否够创建广告创意。
4. `countries` 需要国家代码字符串，还是数组。
5. `daily_budget` 的单位是什么。
6. `btn_type` 可接受哪些枚举值。
7. 图片 URL 和视频 URL 能否被外部系统服务器访问。
8. 图片和视频是否需要外部系统下载并保存到自己的素材库。
9. 素材 URL 是否必须长期有效。
10. 最终 JSON 是否需要增加外部系统自己的字段。
