# 外部系统 Facebook 投放数据分析对接说明（完整异步版）

本文档给外部投放系统开发人员使用。当前对接目标是：外部系统只提交一个 JSON，把 Facebook 广告投放数据、创意信息和素材 URL 传给 AI 系统；AI 系统创建异步分析任务，内部下载素材、生成缩略图/视频关键帧、采集公开来源相似广告参考、调用大模型和规则引擎完成分析；外部系统随后用 `analysis_id` 主动查询结果。

> 当前设计不做主动回调；外部系统不需要提供 `thumbnail_url`、`video_keyframes`；外部系统也不需要提供公开来源搜索词，AI 系统会根据 campaign/adset/creative/insight 自动识别。

---

## 1. 接口总览

基础地址：

```text
https://ai.ggcss.xyz
```

新外部系统主合同：

```http
POST /api/v1/integrations/ad-performance/analysis-jobs
GET  /api/v1/integrations/ad-performance/analysis-jobs/{analysis_id}
```

完整地址：

```http
POST https://ai.ggcss.xyz/api/v1/integrations/ad-performance/analysis-jobs
GET  https://ai.ggcss.xyz/api/v1/integrations/ad-performance/analysis-jobs/{analysis_id}
```

旧接口仍保留给内部/历史同步写入使用，但不是新外部系统主合同：

```http
POST /api/v1/integrations/ad-performance/analyses
```

## 2. 鉴权

推荐请求头：

```http
Authorization: Bearer <AI_ADS_ACCESS_TOKEN>
Content-Type: application/json
```

如果外部系统实现请求头不方便，也支持 URL 参数：


- 不要把 token 写进前端公开代码、日志、截图或 Git 仓库。

## 3. ID 分工：external_request_id 和 analysis_id

### 3.1 external_request_id：外部系统提供，只用于 POST 幂等

外部系统每次提交时必须提供一个唯一的：

```json
"external_request_id": "fb-analysis-20260713-000001"
```

用途：

- 防止网络重试或重复点击导致同一份数据创建多个分析任务。
- 同一个 `external_request_id` + 同一份标准化 payload：返回原来的 `analysis_id`，不会重复创建任务。
- 同一个 `external_request_id` + 不同 payload：返回冲突错误，避免把两份不同数据混成一个任务。

### 3.2 analysis_id：AI 系统生成，只用于 GET 查询

创建任务成功后，AI 系统返回：

```json
"analysis_id": "ana_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
```

外部系统后续只需要保存并使用这个 `analysis_id` 查询：

```http
GET /api/v1/integrations/ad-performance/analysis-jobs/{analysis_id}
```

### 3.3 为什么不提供 GET by external_request_id

当前版本刻意保持查询路径唯一：

- `external_request_id` 只负责创建时幂等。
- `analysis_id` 只负责查询结果。

这样外部人员排查问题时不会混淆“提交 ID”和“查询 ID”。如果未来多账号、多租户、权限隔离变复杂，再扩展联合唯一或额外查询接口。

## 4. POST 创建分析任务

### 4.1 请求

```http
POST https://ai.ggcss.xyz/api/v1/integrations/ad-performance/analysis-jobs
Authorization: Bearer <AI_ADS_ACCESS_TOKEN>
Content-Type: application/json
```

完整推荐结构如下：

```json
{
  "external_request_id": "fb-analysis-20260713-000001",
  "source_type": "external",
  "external_user_id": "5",
  "date_preset": "last_7d",
  "date_start": "2026-06-15",
  "date_stop": "2026-06-21",
  "account_currency": "USD",
  "business_goal": "purchase",
  "campaign": {},
  "adset": {},
  "creative": {},
  "insight": {},
  "siblings": [],
  "metadata_json": {}
}
```

字段说明：

| 字段 | 是否必传 | 说明 |
| --- | --- | --- |
| `external_request_id` | 必传 | 外部系统生成的唯一提交 ID，只用于 POST 幂等。 |
| `source_type` | 建议 | 固定传 `external`。 |
| `external_user_id` | 建议 | 外部系统用户 ID；当前不参与唯一约束。 |
| `date_preset` | 可选 | 如 `last_7d`。 |
| `date_start` / `date_stop` | 建议 | 数据统计周期，格式 `YYYY-MM-DD`。 |
| `account_currency` | 强烈建议 | 币种，如 `USD`、`INR`；用于 CPA/ROAS/金额解读。 |
| `business_goal` | 建议 | 业务目标，如 `purchase`、`lead`、`complete_registration`、`first_recharge`。 |
| `campaign` | 必传 | Facebook 广告系列信息。 |
| `adset` | 必传 | Facebook 广告组、预算、定向、优化目标。 |
| `creative` | 必传 | 广告创意、文案、落地页、图片/视频 URL。 |
| `insight` | 必传 | Facebook 投放成效数据，最关键。 |
| `siblings` | 可选 | 同广告组/同系列下其他广告，用于横向对比。 |
| `metadata_json` | 可选 | 外部系统备注、商品、行业、内部 ID 等。 |

不支持的字段：

| 字段 | 原因 |
| --- | --- |
| `callback_url` | 当前不做主动回调，外部系统自己 GET 查询。 |
| `external_account_id` | 当前不做多账号联合唯一；先只用 `external_request_id`。 |
| `research_context` / `search_keywords` / `competitor_names` | 第一版公开来源采集由系统自动识别，不由外部传。 |

## 5. POST 响应

所有新异步接口都使用统一 envelope：

```json
{
  "code": 1001,
  "message": "accepted",
  "data": {}
}
```

### 5.1 新任务创建成功：HTTP 202 + code 1001

```json
{
  "code": 1001,
  "message": "accepted",
  "data": {
    "analysis_id": "ana_9b8f7c6d5e4a3210abcdef1234567890",
    "external_request_id": "fb-analysis-20260713-000001",
    "status": "queued",
    "stage": "queued",
    "created_at": "2026-07-13T12:00:00Z",
    "poll_url": "https://ai.ggcss.xyz/api/v1/integrations/ad-performance/analysis-jobs/ana_9b8f7c6d5e4a3210abcdef1234567890",
    "idempotent_replay": false
  }
}
```

### 5.2 同 external_request_id + 同 payload 重复提交：HTTP 200 + code 0

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "analysis_id": "ana_9b8f7c6d5e4a3210abcdef1234567890",
    "external_request_id": "fb-analysis-20260713-000001",
    "status": "queued",
    "stage": "queued",
    "created_at": "2026-07-13T12:00:00Z",
    "poll_url": "https://ai.ggcss.xyz/api/v1/integrations/ad-performance/analysis-jobs/ana_9b8f7c6d5e4a3210abcdef1234567890",
    "idempotent_replay": true
  }
}
```

### 5.3 同 external_request_id + 不同 payload：HTTP 409 + code 4001

```json
{
  "code": 4001,
  "message": "external_request_id already exists with a different normalized payload.",
  "data": {}
}
```

处理建议：

- 如果这是同一次提交的重试，请保证 payload 完全一致。
- 如果确实是新数据，请生成新的 `external_request_id`。

### 5.4 参数错误：HTTP 400 + code 4001

常见原因：缺少 `external_request_id`、素材 URL 不是完整 HTTPS、图片广告缺 `creative.image_url`、视频广告缺 `creative.video_url`、传了当前不支持的顶层字段等。

### 5.5 分析队列暂时不可用：HTTP 503 + code 5001

如果 Redis/Celery 暂时无法接收任务，服务端会保留已经生成的 `analysis_id`，并记录本次派发失败。外部系统应使用**完全相同的 `external_request_id` 和 payload**重试 POST；服务端会复用原 `analysis_id` 并重新派发，不会创建第二份分析任务。

```json
{
  "code": 5001,
  "message": "analysis task dispatch failed; retry the same external_request_id",
  "data": {
    "analysis_id": "ana_9b8f7c6d5e4a3210abcdef1234567890",
    "external_request_id": "fb-analysis-20260713-000001"
  }
}
```

## 6. GET 查询分析任务

### 6.1 请求

```http
GET https://ai.ggcss.xyz/api/v1/integrations/ad-performance/analysis-jobs/{analysis_id}
Authorization: Bearer <AI_ADS_ACCESS_TOKEN>
```

### 6.2 queued / processing 响应

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "analysis_id": "ana_9b8f7c6d5e4a3210abcdef1234567890",
    "external_request_id": "fb-analysis-20260713-000001",
    "status": "processing",
    "stage": "media_processing",
    "progress": 30,
    "created_at": "2026-07-13T12:00:00Z",
    "started_at": "2026-07-13T12:00:02Z",
    "completed_at": null,
    "result": null,
    "error": null
  }
}
```

状态说明：

| status | stage 示例 | 说明 |
| --- | --- | --- |
| `queued` | `queued` | 已创建，等待 worker 处理。 |
| `processing` | `rules` | 正在做规则指标计算。 |
| `processing` | `media_processing` | 正在下载图片/视频并生成缩略图/关键帧。 |
| `processing` | `public_research` | 正在采集公开来源相似广告参考。 |
| `processing` | `llm_analysis` | 正在调用大模型生成分析建议。 |
| `succeeded` | `completed` | 分析完成，`result` 有值。 |
| `failed` | `failed` | 分析失败，`error` 有值。 |

## 7. campaign：广告系列

推荐字段：

```json
"campaign": {
  "id": "23",
  "name": "IN Smart TV Sales",
  "fb_id": "120247498350000238",
  "status": "ACTIVE",
  "objective": "OUTCOME_SALES"
}
```

常见 `objective`：

| 值 | 说明 |
| --- | --- |
| `OUTCOME_SALES` | 销售/购买/充值/转化。 |
| `OUTCOME_LEADS` | 表单/潜客。 |
| `OUTCOME_TRAFFIC` | 访问/点击。 |
| `OUTCOME_ENGAGEMENT` | 互动/视频观看。 |
| `OUTCOME_APP_PROMOTION` | 应用安装。 |

建议：如果业务目标是购买、注册、首充，不要只传 `OUTCOME_TRAFFIC`；否则系统会提示“投放目标与业务目标可能不一致”。

## 8. adset：广告组

推荐字段：

```json
"adset": {
  "id": "19",
  "name": "IN - Purchase - 25-45",
  "fb_id": "120247498370850238",
  "status": "ACTIVE",
  "daily_budget": "5000",
  "billing_event": "IMPRESSIONS",
  "optimization_goal": "OFFSITE_CONVERSIONS",
  "bid_strategy": "LOWEST_COST_WITHOUT_CAP",
  "pixel_id": "1234567890",
  "custom_event_type": "purchase",
  "promoted_object": {
    "pixel_id": "1234567890",
    "custom_event_type": "purchase"
  },
  "countries": "IN",
  "age_min": 25,
  "age_max": 45,
  "gender": "male"
}
```

关键点：

- `optimization_goal` 用于判断 Meta 优化目标是否匹配业务目标。
- `pixel_id` / `custom_event_type` / `promoted_object` 有助于判断是否真的在为购买、注册、首充等事件优化。
- `countries`、年龄、性别、人群描述用于受众和投放诊断。


视频广告必须传 `creative_type=video` 和完整 HTTPS `video_url`。

### 9.3 不要传 thumbnail_url / video_keyframes

外部系统不需要传：

```json
"thumbnail_url": "...",
"video_keyframes": []
```

原因：

- AI 系统会下载 `image_url` 或 `video_url`。
- 图片：内部生成缩略图用于模型理解和归档。
- 视频：内部用 ffmpeg 抽关键帧，并生成封面/缩略图。
- 这样外部系统只需要保证素材 URL 可访问，避免双方对缩略图、抽帧时点、画面版本产生不一致。

如果外部系统误传了这两个字段，当前系统不会依赖它们；建议外部新对接直接删除。

### 9.4 素材 URL 约束

当前推荐素材地址形态：

```text
https://newpixel.messrocts.com/uploads/...
```

约束：

- 必须是完整 HTTPS URL。
- 不需要临时签名直链。
- 外部系统和 AI 系统在同一服务器上也仍建议走完整 HTTPS 地址，便于统一下载、日志和排查。
- 当前允许域名由服务端配置控制，默认是 `newpixel.messrocts.com`。

视频建议：

| 项 | 当前建议 |
| --- | --- |
| 常见时长 | 12s |
| 最长时长 | 20s |
| 最大文件 | 100MB |
| 格式 | MP4 / MOV / WebM |
| 优先 | MP4 H.264 |

速度预期：同服务器 HTTPS 场景下，12s、几十 MB 内的视频通常主要耗时在下载和 ffmpeg 抽帧，常见是数秒级；100MB 或服务器 IO/CPU 忙时会更久。即使素材处理失败，任务也会降级分析，不会因为缩略图/抽帧失败直接让整单失败。

## 12. 公开来源相似广告采集

系统提示词的核心目标是：

> 通过采集 Facebook 投放成效、效果较好的相似广告，并给出可执行的优化建议。

这里拆成两类数据源：

1. **外部系统提交的 Facebook 投放成效**：`insight` 里的 spend、impressions、clicks、purchase、ROAS 等，视为已验证的投放事实。
2. **系统自动采集的公开来源相似广告**：第一版使用公开网页/公开来源搜索相似广告，只作为创意模式、卖点、Hook、CTA、素材结构等 proxy signal。

重要边界：

- 公开来源可以帮助发现“类似广告怎么写、怎么展示、强调什么卖点”。
- 公开来源不能证明对方真实 CTR、CPC、CPA、purchase、revenue、ROAS。
- 分析结果最多返回 3 条 `market_intelligence.references`，只保留公开广告主、来源地址、观察到的创意模式和可借鉴思路。
- `market_intelligence.limitation` 会明确说明公开来源不能验证真实投放成效。
- 如果公开采集超时或失败，任务仍会继续完成，`market_intelligence.status` 返回 `partial` 或 `unavailable`，不会把公开创意模式写成已验证的高成效结论。

公开来源采集由系统自动识别，不需要外部系统传关键词、竞品名或搜索条件。

## 13. result 结构：facebook_ad_analysis_v1

只有任务满足以下状态时，`data.result` 才有值：

```json
{
  "status": "succeeded",
  "stage": "completed",
  "progress": 100
}
```

排队、处理中或执行失败时，`result` 为 `null`。成功结果严格使用下面的顶层合同，不再返回旧版的大型指标树：

```json
{
  "schema_version": "facebook_ad_analysis_v1",
  "platform": "facebook",
  "summary": "",
  "overall_decision": {},
  "targeting_analysis": [],
  "adjustment_plans": [],
  "copywriting_analysis": {},
  "media_analysis": {},
  "market_intelligence": {},
  "data_gaps": []
}
```

### 13.1 外部系统应该怎么展示

本版本的目标是让运营人员直接看到“结论是什么、先做什么、为什么做”，而不是先理解大量指标对象。建议结果页按以下顺序展示：

1. `summary`：页面顶部的一句话结论。
2. `overall_decision`：扩量、优化、观察或暂停，以及当前优先级和主要问题。
3. `adjustment_plans`：按返回顺序展示具体操作，第一条是当前最优先动作。
4. 有需要时再展开 `targeting_analysis`、`copywriting_analysis`、`media_analysis`、`market_intelligence` 和 `data_gaps`。

> 外部系统应优先展示 `summary`、`overall_decision` 和 `adjustment_plans`。不要再依赖旧版 `performance_funnel` 等字段拼装运营结论。

### 13.2 顶层字段含义

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `schema_version` | string | 固定为 `facebook_ad_analysis_v1`。版本名保持不变，但字段结构已简化。 |
| `platform` | string | 固定为 `facebook`。 |
| `summary` | string | 100 字以内的总体结论，直接指出当前问题和最先执行的方向。 |
| `overall_decision` | object | 规则和投放数据得出的总体动作、优先级和主要问题。 |
| `targeting_analysis` | array | 只返回确实值得处理的国家、人群、年龄、性别、设备或版位问题；没有明确问题时为空数组。 |
| `adjustment_plans` | array | 1～5 条可直接交给运营执行的调整计划，按优先级排序。 |
| `copywriting_analysis` | object | 当前文案问题、修改建议，以及在原文案信息足够时给出的推荐文案。 |
| `media_analysis` | object | 图片或视频的素材总结和具体修改位置；素材处理失败时只说明失败，不编造画面观察。 |
| `market_intelligence` | object | 公开来源相似广告中可参考的创意模式、应用方式及证据限制。 |
| `data_gaps` | array | 会影响当前判断的重要缺失数据，最多 3 条。 |

### 13.3 `overall_decision`：总体判断

```json
{
  "action": "optimize",
  "priority": "high",
  "main_problem": "点击进入落地页后的流失较高"
}
```

| 字段 | 可选值/说明 |
| --- | --- |
| `action` | `scale` 扩量、`optimize` 优化、`monitor` 继续观察、`pause` 暂停。 |
| `priority` | `high`、`medium`、`low`。 |
| `main_problem` | 100 字以内，只保留当前最主要的问题。 |

总体动作、优先级、主要瓶颈、指标计算和数据缺失事实由系统规则控制；大模型负责把结果写得清晰、具体，不会覆盖这些事实。

### 13.4 `targeting_analysis`：定向建议

每项结构如下：

```json
{
  "dimension": "country",
  "current": "IN、ID 共用一个广告组预算。",
  "decision": "test",
  "problem": "多个市场共用预算，无法单独验证各市场是否适合当前产品和创意。",
  "suggestion": "保留原广告组，复制广告组并分别设置国家，用小预算做对照测试。",
  "reason": "当前没有国家拆分成效，因此不能直接判断哪个国家表现更好。"
}
```

枚举：

- `dimension`：`country`、`audience`、`age`、`gender`、`device`、`placement`。
- `decision`：`adjust`、`test`、`monitor`。
- 数组最多 3 项，只返回有明确问题或验证价值的维度。

**无拆分数据时的硬性规则：**如果请求中没有国家、年龄、性别、设备或版位拆分成效，系统不会声称“某国家 ROAS 更高”“某年龄 CTR 更好”或“移动端 CPA 更低”。此时只能建议：保留原广告组，复制广告组，单独修改一个维度并进行小预算测试；不能把推测写成已验证结论，也不应直接删除其他人群。

### 13.5 `adjustment_plans`：运营执行计划

每项结构如下：

```json
{
  "priority": "high",
  "category": "landing_page",
  "title": "检查点击到落地页的流失",
  "action": "检查移动端页面加载、广告链接跳转和 Meta Pixel 落地页事件回传。",
  "reason": "链接点击数量明显高于落地页浏览数量。",
  "expected_effect": "减少点击后的流失，提高有效落地页访问量。",
  "what_to_watch": "观察落地页浏览量、落地页浏览率和后续购买是否改善。"
}
```

枚举和规则：

- `priority`：`high`、`medium`、`low`。
- `category`：`landing_page`、`tracking`、`copywriting`、`media`、`targeting`、`budget`、`campaign_setup`。
- 数组最少 1 项、最多 5 项。
- 第一项应对应 `overall_decision.main_problem`，并且是运营当前最应该先执行的动作。
- `action` 必须写清具体操作，`reason` 写数据依据，`what_to_watch` 写修改后观察什么，不返回“优化素材”“继续观察”一类空泛建议。

### 13.6 `copywriting_analysis`：文案建议

```json
{
  "summary": "当前文案有明确场景，但核心利益点出现较晚。",
  "problems": [
    "首句没有立即说明优惠或购买理由。"
  ],
  "suggestions": [
    "把最强利益点放在首句，并让标题只表达一个重点。"
  ],
  "recommended_primary_text": "推荐的 Primary Text；无法可靠重写时为 null",
  "recommended_headline": "推荐的 Headline；无法可靠重写时为 null",
  "recommended_description": "推荐的 Description；无法可靠重写时为 null"
}
```

限制：

- `summary` 最多 100 字。
- `problems` 最多 3 项。
- `suggestions` 最多 3 项。
- 推荐文案尽量保持原广告所使用的语言；如果请求没有提供足够的原文案和产品信息，三个推荐字段可以返回 `null`，不会凭空编造优惠、承诺或价格。

### 13.7 `media_analysis`：图片/视频素材建议

```json
{
  "media_type": "video",
  "summary": "开场利益点出现较晚，前3秒可更快展示产品和优惠。",
  "improvements": [
    {
      "location": "0至3秒",
      "problem": "产品和核心利益点出现较晚。",
      "action": "第一秒展示产品，并叠加一个核心利益点。"
    }
  ]
}
```

限制：

- `media_type`：`image` 或 `video`。
- `summary` 最多 100 字。
- `improvements` 最多 3 项，每项指出修改位置、问题和具体动作。

外部系统仍然只需要提供 `creative.image_url` 或 `creative.video_url`，缩略图和视频关键帧由 AI 系统生成。**如果下载、解码、缩略图生成或 ffmpeg 抽帧失败，`media_analysis` 只会说明素材未能完成处理，`improvements` 返回空数组；不会编造“前3秒出现了什么”“图片颜色不醒目”等画面观察。**

### 13.8 `market_intelligence`：公开来源创意参考

```json
{
  "status": "completed",
  "summary": "相似广告常把产品画面和价格利益点前置，可用于创意结构参考。",
  "references": [
    {
      "advertiser_name": "Example Advertiser",
      "source_url": "https://www.facebook.com/ads/library/?id=1234567890",
      "observed_pattern": "开场先展示产品，再快速给出一个利益点。",
      "applicable_idea": "测试第一秒出现产品，并在前三秒内只传达一个核心卖点。"
    }
  ],
  "limitation": "公开来源只能参考创意模式，不能证明真实 CTR、CPC、CPA、购买量、收入或 ROAS。"
}
```

枚举和限制：

- `status`：`completed`、`partial`、`unavailable`。
- `summary` 最多 100 字。
- `references` 最多 3 项；没有可靠参考时可以为空数组。
- 公开来源可以用来参考 Hook、卖点、CTA、画面结构和表达方式，但不能访问其他广告主的真实后台投放数据。因此，公开来源**不能证明**参考广告具有更高的 CTR、更低的 CPC/CPA，或更高的购买量、收入、ROAS。

### 13.9 `data_gaps`：影响判断的缺失数据

`data_gaps` 最多 3 项，只列出会实质影响结论或下一步操作的数据缺口，例如：

```json
[
  "缺少购买金额，因此暂时无法判断真实 ROAS。",
  "没有落地页浏览事件，需要先检查 Pixel/CAPI 回传。"
]
```

如果缺失项不影响当前结论，不需要为了凑数量而返回。

### 13.10 字段与数组限制汇总

| 位置 | 限制 |
| --- | --- |
| `summary` | 最多 100 字。 |
| `targeting_analysis` | 最多 3 项。 |
| `adjustment_plans` | 最少 1 项、最多 5 项。 |
| `copywriting_analysis.problems` | 最多 3 项。 |
| `copywriting_analysis.suggestions` | 最多 3 项。 |
| `media_analysis.improvements` | 最多 3 项。 |
| `market_intelligence.references` | 最多 3 项。 |
| `data_gaps` | 最多 3 项。 |

### 13.11 从旧结果字段迁移

新接口路径、异步任务、`external_request_id`、`analysis_id` 和 `schema_version` 都不变；只有 `result` 从指标型大型结构改成运营建议型结构。

| 旧字段 | 新字段/处理方式 |
| --- | --- |
| `executive_summary` | 改读 `summary` 和 `overall_decision`。 |
| `objective_alignment` | 目标错配结论并入 `overall_decision`；具体操作并入 `adjustment_plans`。 |
| `performance_funnel` | 不再公开整个指标树；关键瓶颈、数据依据和观察指标并入 `summary`、`overall_decision`、`adjustment_plans`。 |
| `diagnoses` | 主要问题并入 `overall_decision.main_problem`；可执行处理并入 `adjustment_plans`。 |
| `creative_analysis` | 拆分为 `copywriting_analysis` 和 `media_analysis`。 |
| `audience_and_delivery_analysis` | 改读 `targeting_analysis`；预算或投放设置动作改读 `adjustment_plans`。 |
| `recommended_actions` | 改读 `adjustment_plans`。 |
| `recommended_changes` | 不再返回直接覆盖式参数；定向修改改为 `targeting_analysis` 和小预算测试计划。 |
| `experiment_plan` | 合并到 `adjustment_plans`，通过 `action`、`expected_effect`、`what_to_watch` 表达。 |
| `data_quality` | 改读 `data_gaps`。 |
| `market_intelligence` | 字段名保留，但结构简化为 `status`、`summary`、`references`、`limitation`。 |
| `benchmark_comparison` | 不再作为独立顶层字段；有可靠对比结论时并入总体判断或调整计划。 |
| `analysis_metadata` | 不再向外部系统公开。 |

外部系统升级时，应删除对旧字段的强依赖。新结果顶层只允许本文列出的字段，不要同时兼容或展示两套结果结构。

## 14. 外部系统推荐轮询策略

建议：

1. POST 创建任务后保存 `analysis_id`。
2. 2 秒后第一次 GET。
3. 如果是 `queued` / `processing`，每 3-5 秒轮询一次。
4. 最长等待可先设 2-5 分钟；超时后前端显示“分析中”，后台继续允许用户刷新。
5. 遇到 `succeeded` 展示 `result`。
6. 遇到 `failed` 展示 `error.message`，并把 `analysis_id` / `external_request_id` 发给我方排查。

不要在轮询时重新 POST；GET 只用 `analysis_id`。

## 17. 服务端配置摘要

当前实现使用独立分析队列：

```text
queue_name: ad_analysis_queue
worker: worker_ad_analysis
task_type: ad_performance_analysis
business_type: ad_performance_analysis
```

关键环境变量：

```env
AD_ANALYSIS_QUEUE_CONCURRENCY=2
MODEL_PROVIDER_AD_ANALYSIS_CONCURRENCY=2
AD_ANALYSIS_MEDIA_PROCESSING_ENABLED=true
AD_ANALYSIS_ALLOWED_MEDIA_HOSTS=newpixel.messrocts.com
AD_ANALYSIS_ALLOW_PRIVATE_MEDIA_HOSTS=false
AD_ANALYSIS_MEDIA_DOWNLOAD_TIMEOUT_SECONDS=20
AD_ANALYSIS_FFPROBE_TIMEOUT_SECONDS=10
AD_ANALYSIS_FFMPEG_FRAME_TIMEOUT_SECONDS=15
AD_ANALYSIS_IMAGE_DOWNLOAD_MAX_BYTES=26214400
AD_ANALYSIS_VIDEO_MAX_DURATION_SECONDS=20
AD_ANALYSIS_VIDEO_DOWNLOAD_MAX_BYTES=104857600
AD_ANALYSIS_PUBLIC_RESEARCH_ENABLED=true
PUBLIC_RESEARCH_ENABLED=true
AD_ANALYSIS_PUBLIC_RESEARCH_TIMEOUT_SECONDS=6
AD_ANALYSIS_PUBLIC_RESEARCH_MAX_RESULTS=3
```

说明：

- `AD_ANALYSIS_ALLOW_PRIVATE_MEDIA_HOSTS` 默认必须保持 `false`。如果 `newpixel.messrocts.com` 在服务器上确实解析到私网 IP，运维可在真实 `.env.production` 中显式改为 `true`；这是高风险例外开关，即使开启也仍只允许 `AD_ANALYSIS_ALLOWED_MEDIA_HOSTS` 中的域名。
- 默认开启公开来源采集；`AD_ANALYSIS_PUBLIC_RESEARCH_ENABLED=false` 或 `PUBLIC_RESEARCH_ENABLED=false` 时不联网采集公开来源，但仍会基于提交数据和素材做分析。
- 公开来源采集开启时，失败/超时只降级，不让整单失败。
- Docker 镜像需要 `ffmpeg`，用于视频抽帧。
- Python 依赖需要 `Pillow`，用于图片缩略图。

## 18. 外部系统上线前检查清单

外部系统需要确认：

- [ ] 每次提交都有唯一 `external_request_id`。
- [ ] 重试同一次提交时，payload 保持一致。
- [ ] 保存 POST 返回的 `analysis_id`。
- [ ] 查询结果只用 `analysis_id`。
- [ ] 不等待 callback。
- [ ] 图片广告传 `creative.creative_type=image` 和 `creative.image_url`。
- [ ] 视频广告传 `creative.creative_type=video` 和 `creative.video_url`。
- [ ] 不传 `thumbnail_url` / `video_keyframes`。
- [ ] 素材 URL 是 `https://newpixel.messrocts.com/uploads/...` 这种完整 HTTPS 地址。
- [ ] 尽量传 `account_currency`、`actions`、`action_values`、视频播放分位数据。
- [ ] 出错时记录 `external_request_id`、`analysis_id`、HTTP 状态码和响应 body。
