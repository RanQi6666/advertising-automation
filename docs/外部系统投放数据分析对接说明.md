# 外部系统 Facebook 投放数据分析接口联调手册

> **版本：** v1.0
>
> **适用对象：** 外部投放系统开发、测试和运营人员
>
> **接口基础地址：** `https://ai.ggcss.xyz`

> **处理逻辑说明：** 如需了解提交后的规则计算、素材下载与抽帧、公开来源创意参考、大模型建议生成及降级边界，请阅读 [《外部系统 Facebook 投放数据分析处理流程说明》](./外部系统Facebook投放数据分析处理流程说明.md)。

## 1. 对接目标与边界

外部系统将一条 Facebook 广告的投放数据、创意信息和主素材 URL 组装为一个 JSON，提交给 AI 系统。AI 系统异步完成指标计算、主素材处理、公开来源创意参考和大模型分析；外部系统通过轮询查询结果，并将建议展示给运营人员。

```text
外部系统 POST 一份 JSON
        ↓
AI 系统创建异步分析任务，返回 analysis_id
        ↓
外部系统使用 analysis_id 轮询 GET
        ↓
status = succeeded 后读取 result，展示给运营人员
```

### 系统自动处理与接口边界

- **轮询查询**：系统不做主动回调；外部系统使用 `analysis_id` 查询任务和结果。
- **主素材处理**：系统根据主素材 URL 自行下载图片或视频，并生成缩略图、视频关键帧和实际媒体信息。
- **事件成本计算**：系统按 `spend / actions[].value` 自动计算每类事件的单次成本。
- **金额口径**：所有金额按 **USD** 解读；业务目标由广告配置与事件自动识别。
- **公开来源创意研究**：系统根据已提交的广告信息自动识别研究方向。
- **素材地址**：素材 URL 只需为 AI 系统服务器可下载的完整公开 `http://` 或 `https://` 地址，不限定来源域名。

> 公开来源研究仅用于发现相似广告的 Hook、卖点、CTA 和素材结构。它不能证明其他广告主真实的 CTR、CPC、CPA、购买量、收入或 ROAS。

## 3. 五分钟跑通

1. 按第 5 节准备一个请求 JSON，并为本次新分析生成 `external_request_id`。
2. 调用 POST 创建任务。
3. 保存响应中的 `data.analysis_id`（也可直接保存 `data.poll_url`；该地址始终按系统配置的正式外部基础地址生成，例如 `https://ai.ggcss.xyz`，不会受内部 HTTP 反向代理影响）。
4. 约 2 秒后开始调用 GET；当状态仍为 `queued` 或 `processing` 时，每 3～5 秒查询一次。
5. 当 `data.status = "succeeded"` 时读取 `data.result`；当 `failed` 时展示 `data.error.message` 并保留两个 ID 供排查。

**不要因为轮询未完成而重新创建任务。** 轮询只使用 `analysis_id` 调用 GET。

## 4. ID、幂等与重试规则



### 4.1 `external_request_id`：外部生成的 POST 幂等键

外部系统每发起一次**新分析**，必须生成一个非空、最长 128 个字符的唯一 ID，例如：

```json
"external_request_id": "fb-analysis-20260715-000001"
```

它只用于防止网络重试、重复点击或超时重发产生重复任务：


| 场景                | POST 结果                       | 外部系统处理                          |
| ----------------- | ----------------------------- | ------------------------------- |
| 同一 ID + 相同规范化请求数据 | HTTP `200`，返回原任务              | 复用返回的 `analysis_id`             |
| 同一 ID + 不同请求数据    | HTTP `409`                    | 新数据必须生成新的 `external_request_id` |
| 队列派发失败            | HTTP `503`，仍会返回 `analysis_id` | 用**相同 ID 和相同 JSON**重试 POST      |


为避免 409，重试时请保持请求 JSON 的业务数据一致；不要重新排序后改变含义、追加字段或修改数值。

### 4.2 `analysis_id`：AI 系统生成的查询键

创建成功后，AI 系统生成并返回：

```json
"analysis_id": "ana_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx"
```

外部系统保存它，并且只通过以下接口查询：

```http
GET /api/v1/integrations/ad-performance/analysis-jobs/{analysis_id}
```

本版本**不提供**按 `external_request_id` 查询的 GET 接口。

## 5. POST 创建任务



### 5.1 请求

```http
POST https://ai.ggcss.xyz/api/v1/integrations/ad-performance/analysis-jobs
Authorization: Bearer <AI_ADS_ACCESS_TOKEN>
Content-Type: application/json
```



### 5.2 字段分级总览

以下为外部合同中每个部分**当前已定义、已识别的字段**。字段标记含义：

| 标记 | 含义 |
| --- | --- |
| **必传** | 缺失会被接口拒绝，无法创建任务。 |
| **条件必传** | 是否必传取决于其他字段或投放模式。 |
| **条件可选** | 仅在满足指定业务条件时提供。 |
| **可选（强烈建议）** | 不传不会被接口拒绝，但会明显影响结论、建议或可追溯性。 |
| **可选** | 不传不影响任务创建；有数据时可增强分析。 |

> `campaign`、`adset`、`insight`、`siblings`、`metadata_json` 对象本身不是接口硬性必传项，空对象也可创建任务；但这仅代表“能创建”，不代表“有足够数据可分析”。生产接入请至少提交“建议最小数据集”。

#### 顶层字段完整清单

| 字段 | 必传情况 | 格式 / 可选值 | 说明 |
| --- | --- | --- | --- |
| `external_request_id` | **必传** | 非空字符串，最长 128 字符 | 外部系统生成的幂等键。同一 ID 只能对应同一份规范化业务数据。 |
| `source_type` | 可选 | 字符串；默认 `external` | 数据来源标记。 |
| `date_preset` | 可选 | 字符串，例如 `last_7d` | 外部侧统计周期描述。 |
| `date_start` | 可选（强烈建议） | `YYYY-MM-DD` | 成效统计开始日期。 |
| `date_stop` | 可选（强烈建议） | `YYYY-MM-DD` | 成效统计结束日期。 |
| `campaign` | 可选（强烈建议） | 对象 | 广告系列字段见 [6.1](#61-campaign广告系列字段完整清单)。 |
| `adset` | 可选（强烈建议） | 对象 | 广告组字段见 [6.2](#62-adset广告组字段完整清单)。 |
| `creative` | **必传** | 对象 | 必须包含 `creative_type` 和对应主素材 URL，字段见 [6.3](#63-creative创意文案与主素材字段完整清单)。 |
| `insight` | 可选（强烈建议） | 对象 | Facebook 成效快照，字段见 [6.4](#64-insight投放成效快照字段完整清单)。 |
| `siblings` | 可选 | 数组，默认 `[]` | 同组广告对比数据，字段见 [6.5](#65-siblings同组广告横向对比字段完整清单)。 |
| `metadata_json` | 可选 | 对象，默认 `{}` | 业务补充信息，字段见 [6.6](#66-metadata_json业务补充信息字段完整清单)。 |

#### 建议最小数据集

为让系统能够给出有依据的运营建议，每次至少建议传递：

```text
external_request_id
+ creative.creative_type 和对应主素材 URL
+ campaign.name / campaign.objective
+ adset.name / adset.optimization_goal / adset.custom_event_type（如适用）
+ insight.spend / insight.impressions / insight.clicks / insight.actions
+ date_start / date_stop
```

#### 对象内的其他扩展字段

为兼容外部系统演进，`campaign`、`adset`、`creative`、`insight`、`siblings[*]`、`metadata_json` 中未列出的自定义字段目前可以随请求保存，不会因为“未知字段”直接被拒绝；但它们**不属于稳定分析合同**，系统不保证会读取、计算或展示。外部系统请以第 6 节列出的字段为准，不要依赖未列字段影响分析结论。

### 5.4 创建成功响应

新任务创建成功时返回 HTTP `202`：

```json
{
  "code": 1001,
  "message": "accepted",
  "data": {
    "analysis_id": "ana_9b8f7c6d5e4a3210abcdef1234567890",
    "external_request_id": "fb-analysis-20260715-000001",
    "status": "queued",
    "stage": "queued",
    "created_at": "2026-07-15T12:00:00Z",
    "poll_url": "https://ai.ggcss.xyz/api/v1/integrations/ad-performance/analysis-jobs/ana_9b8f7c6d5e4a3210abcdef1234567890",
    "idempotent_replay": false
  }
}
```

任务可能很快进入 `processing` 或 `succeeded`；请以响应实际返回的状态为准。

## 6. 请求对象字段说明



### 6.1 `campaign`：广告系列字段完整清单

```json
"campaign": {
  "id": "campaign_001",
  "name": "IN Smart TV Sales",
  "status": "ACTIVE",
  "objective": "OUTCOME_SALES",
  "daily_budget": "500.00",
  "bid_strategy": "LOWEST_COST_WITHOUT_CAP",
  "switch_time": "9-18"
}
```


| 字段 | 必传情况 | 类型 / 示例 | 字段含义与使用方式 |
| --- | --- | --- | --- |
| `id` | 可选（强烈建议） | 字符串，例如 `campaign_001` | 外部系统内的广告系列唯一标识。用于任务记录和排查。 |
| `name` | 可选（强烈建议） | 字符串 | 广告系列名称。用于识别投放主题，并辅助系统理解分析上下文和公开创意研究方向。 |
| `status` | 可选 | 字符串，例如 `ACTIVE`、`PAUSED` | 广告系列当前状态，仅作上下文记录；本接口不据此修改广告。 |
| `objective` | 可选（强烈建议） | 字符串，例如 `OUTCOME_SALES` | Facebook 广告系列投放目标。系统会结合广告组优化目标检查配置一致性。常见值包括 `OUTCOME_SALES`、`OUTCOME_LEADS`、`OUTCOME_TRAFFIC`、`OUTCOME_ENGAGEMENT`、`OUTCOME_APP_PROMOTION`。 |
| `daily_budget` | 可选（有 CBO 预算时强烈建议） | 非负数或数字字符串，例如 `500.00` | 广告系列日预算，统一按 USD 解释。CBO 场景下，它是多个广告组共享、由 Meta 自动分配的预算。 |
| `bid_strategy` | 可选（有系列出价策略时建议） | 见下表 | CBO 场景下的广告系列统一出价策略。若传入，必须是下表允许值。 |
| `switch_time` | 可选 | `HH-HH`，例如 `9-18`、`18-9`、`0-0` | 广告系列每日允许开启的时间窗口，使用广告账户时区。`0-0` 代表不限制；跨午夜写法合法。 |


`campaign.bid_strategy` 可选值：


| 值                           | 中文含义          |
| --------------------------- | ------------- |
| `LOWEST_COST_WITHOUT_CAP`   | 最低成本（无上限）     |
| `LOWEST_COST_WITH_BID_CAP`  | 最低成本（有出价上限）   |
| `LOWEST_COST_WITH_MIN_ROAS` | 最低成本（最低 ROAS） |




### 6.2 `adset`：广告组字段完整清单（区分 CBO 与 ABO）

```json
"adset": {
  "id": "adset_001",
  "name": "IN - Purchase - 25-45",
  "daily_budget": null,
  "billing_event": "IMPRESSIONS",
  "optimization_goal": "OFFSITE_CONVERSIONS",
  "custom_event_type": "PURCHASE",
  "countries": "IN",
  "age_min": 25,
  "age_max": 45,
  "genders": "ALL",
  "device_platforms": "mobile",
  "placements": ["facebook_feed", "instagram_feed"],
  "scale_threshold": "8.50",
  "stop_threshold": "20.00",
  "switch_time": "9-18"
}
```



#### 预算与出价


| 场景         | `campaign.daily_budget` | `adset.daily_budget` | `adset.bid_strategy`                     |
| ---------- | ----------------------- | -------------------- | ---------------------------------------- |
| CBO：广告系列预算 | 传实际日预算                  | 传 `null` 或不传         | 出价策略由 `campaign.bid_strategy` 统一表达 |
| ABO：广告组预算  | 可按实际数据传                 | 传大于 0 的实际日预算         | 可传，值与 campaign 出价策略枚举相同                  |


当 `adset.daily_budget` 有有效金额时，才允许传 `adset.bid_strategy`。CBO 下广告系列预算由广告组共享并由 Meta 自动分配。

#### 广告组全部字段

| 字段 | 必传情况 | 类型 / 示例 | 字段含义与使用方式 |
| --- | --- | --- | --- |
| `id` | 可选（强烈建议） | 字符串，例如 `adset_001` | 外部系统内广告组唯一标识，用于记录和排查。 |
| `name` | 可选（强烈建议） | 字符串 | 广告组名称，帮助识别受众、地区或测试策略。 |
| `status` | 可选 | 字符串，例如 `ACTIVE`、`PAUSED` | 广告组当前投放状态，仅作为上下文，不触发任何自动修改。 |
| `daily_budget` | 可选；**传 `adset.bid_strategy` 时条件必传且必须大于 0** | 非负数、数字字符串或 `null` | 广告组日预算，统一按 USD 解释。ABO 有实际广告组预算时传实际金额；CBO 可传 `null` 或不传。 |
| `bid_strategy` | 条件可选 | `LOWEST_COST_WITHOUT_CAP`、`LOWEST_COST_WITH_BID_CAP`、`LOWEST_COST_WITH_MIN_ROAS` | 当 `daily_budget` 为大于 0 的广告组预算（ABO）时可提供，表示广告组自身出价策略。 |
| `billing_event` | 可选（强烈建议） | `IMPRESSIONS` 或 `LINK_CLICKS` | 计费方式：`IMPRESSIONS` 为按展示计费，`LINK_CLICKS` 为按链接点击计费。 |
| `optimization_goal` | 可选（强烈建议） | 见下表 | 广告组优化目标。系统用它判断投放目标与事件、广告系列目标是否一致。 |
| `pixel_id` | 可选 | 字符串 | 关联的 Meta Pixel ID，仅作转化追踪上下文和排查信息。 |
| `custom_event_type` | 可选（站外转化 / 业务事件优化时强烈建议） | 见下表 | 优化事件名称，例如购买、注册、首充。系统据此将“消耗 / 对应事件数”解释为阈值中的单次成效成本。 |
| `promoted_object` | 可选 | 对象，例如 `{ "pixel_id": "...", "custom_event_type": "PURCHASE" }` | Meta 推广对象补充信息。可提供 Pixel 与优化事件，辅助识别转化配置。 |
| `countries` | 可选（有地域定向时建议） | 字符串或外部系统可读的地区描述，例如 `IN` | 当前投放国家 / 地区定向。没有国家拆分成效时，系统只会给测试建议，不会认定某地区实际表现更好或更差。 |
| `age_min` | 可选 | 整数，例如 `18` | 定向年龄下限。与 `age_max` 一起形成当前年龄范围。 |
| `age_max` | 可选 | 整数，例如 `45` | 定向年龄上限。与 `age_min` 一起形成当前年龄范围。 |
| `genders` | 可选 | `ALL`、`MALE`、`FEMALE` | 当前性别定向：`ALL` 为不限，`MALE` 为男，`FEMALE` 为女。 |
| `audience` | 可选 | 字符串 | 人群定向的简要描述，例如兴趣包、类似受众或宽泛人群。 |
| `device_platforms` | 可选 | 字符串或数组，例如 `mobile` | 当前设备定向，例如移动端、桌面端或不限。 |
| `placements` | 可选 | 数组，例如 `["facebook_feed", "instagram_feed"]` | 当前版位定向，用于让结果说明当前投放版位和建议测试方向。 |
| `scale_threshold` | 可选 | 非负数字，USD / 成效，例如 `8.50` | 加量阈值：当消耗 / 对应优化事件次数低于该值时，外部运营策略可考虑自动加量。系统不直接执行加量，只分析和展示建议。 |
| `stop_threshold` | 可选 | 非负数字，USD / 成效，例如 `20.00` | 停止阈值：当消耗 / 对应优化事件次数高于该值时，外部运营策略可考虑自动停止。若同时传阈值，必须大于 `scale_threshold`。 |
| `switch_time` | 可选 | `HH-HH`，例如 `9-18`、`18-9`、`0-0` | ABO 广告组每日允许开启的时间窗口，使用广告账户时区；跨午夜合法。 |

#### 优化目标与优化事件的可选值

| 字段 | 可选值 | 对应含义 |
| --- | --- | --- |
| `optimization_goal` | `LINK_CLICKS` | 链接点击 |
| `optimization_goal` | `LANDING_PAGE_VIEWS` | 落地页浏览 |
| `optimization_goal` | `OFFSITE_CONVERSIONS` | 站外转化 |
| `optimization_goal` | `THRUPLAY` | 视频播放 |
| `optimization_goal` | `APP_INSTALLS` | 应用安装 |
| `optimization_goal` | `LEAD_GENERATION` | 潜在客户 |
| `custom_event_type` | `COMPLETE_REGISTRATION` | 完成注册；也接受 `COMPLETE-REGISTRATION`，系统会标准化。 |
| `custom_event_type` | `PURCHASE` | 购买 |
| `custom_event_type` | `ADD_TO_CART` | 加入购物车 |
| `custom_event_type` | `INITIATED_CHECKOUT` | 发起结账 |
| `custom_event_type` | `SEARCH` | 搜索行为 |
| `custom_event_type` | `ADD_PAYMENT_INFO` | 添加支付信息 |
| `custom_event_type` | `FIRST_RECHARGE` | 首充 |


阈值中的“成效”取 `custom_event_type` 对应的 `insight.actions` 事件次数。例如 `custom_event_type=PURCHASE` 时，消耗 100 USD、购买 10 次，CPA 为 10 USD/购买。

`switch_time` 使用广告账户时区，开始时间包含、结束时间不包含：


| 值      | 含义                                |
| ------ | --------------------------------- |
| `0-0`  | 全天不限制。                            |
| `9-18` | 每天 09:00（含）至 18:00（不含）自动开启。       |
| `18-9` | 每天 18:00（含）至次日 09:00（不含）自动开启，跨午夜。 |


除 `0-0` 外，开始小时和结束小时不可相同；开始小时大于结束小时合法，表示跨午夜。

| `btn_type` | 可选（建议） | 见下表 | 广告行动按钮类型。可传显示名或代码，系统会标准化。 |
| `link` | 可选（建议） | 完整 URL | 广告点击后的落地页地址。用于理解 CTA 与落地页上下文。 |
| `ad_status` | 可选 | 字符串，例如 `ACTIVE`、`PAUSED` | 广告当前状态，用于运营上下文。 |

`btn_type` 可传下列显示名或对应大写代码；服务端会标准化：


| 显示名                | 代码                   |

### 6.4 `insight`：投放成效快照字段完整清单

```json
"insight": {
  "status": "ACTIVE",
  "spend": "100.00",
  "impressions": "50000",
  "reach": "42000",
  "frequency": "1.19",
  "clicks": "860",
  "ctr": "1.60",
  "cpc": "0.125",
  "cpm": "2.00",
  "actions": [
    {"action_type": "landing_page_view", "value": "500"},
    {"action_type": "purchase", "value": "10"}
  ]
}
```


| 字段 | 必传情况 | 类型 / 示例 | 字段含义与使用方式 |
| --- | --- | --- | --- |
| `status` | 可选 | `ACTIVE` 或 `PAUSED` | 此广告的当前投放开关状态；不是分析任务状态。若传只能使用这两个值，大小写会标准化。 |
| `date_start` | 可选 | `YYYY-MM-DD` | 此成效快照自身的开始日期。顶层已经传日期时可不重复；若两处都有，请保持一致。 |
| `date_stop` | 可选 | `YYYY-MM-DD` | 此成效快照自身的结束日期。顶层已经传日期时可不重复；若两处都有，请保持一致。 |
| `spend` | 可选（强烈建议） | 非负数或数字字符串，例如 `100.00` | 统计周期内广告消耗，统一按 USD 解读；是所有成本和事件 CPA 计算的分子。 |
| `impressions` | 可选（强烈建议） | 非负整数或数字字符串，例如 `50000` | 广告被展示的总次数，用于计算 CPM、视频播放率等。 |
| `reach` | 可选（建议） | 非负整数或数字字符串 | 被广告覆盖的去重人数。与 `impressions` 一起解释频次。 |
| `frequency` | 可选（建议） | 非负数，例如 `1.19` | 平均每个覆盖用户看到广告的次数。可直接传；缺失时系统会标记为数据缺口，不把它当作已计算事实。 |
| `clicks` | 可选（强烈建议） | 非负整数或数字字符串 | 广告的全部点击次数。外部无法提供链接点击时，系统仍以此和事件数据做分析。 |
| `inline_link_clicks` | 可选 | 非负整数或数字字符串 | 链接点击次数。缺失时可不传，但“链接点击 → 落地页浏览”的细漏斗结论会降级。 |
| `ctr` | 可选（建议） | 百分比数值，例如 `1.46` | 全部点击率，`1.46` 代表 1.46%。缺失时系统会标记为数据缺口，不把它当作已计算事实。 |
| `inline_link_click_ctr` | 可选 | 百分比数值，例如 `1.20` | 链接点击率。外部无法提供时可不传。 |
| `cpc` | 可选 | 非负数或数字字符串，例如 `0.125` | 每次全部点击成本，USD。缺失时系统会标记为数据缺口，不把它当作已计算事实。 |
| `cpm` | 可选 | 非负数或数字字符串，例如 `2.00` | 每千次展示成本，USD。缺失时系统会标记为数据缺口，不把它当作已计算事实。 |
| `actions` | 可选（强烈建议） | `[{"action_type":"purchase","value":"10"}]` | Facebook 转化 / 行为事件次数数组。`value` 表示次数，不是金额。系统用它识别购买、注册、首充、加购、线索、落地页浏览等，并自行计算每类事件 CPA。 |
| `video_play_actions` | 可选（视频广告强烈建议） | 事件数组 | 视频播放次数数组，用于计算视频播放率和后续播放留存。 |
| `video_p25_watched_actions` | 可选（视频广告建议） | 事件数组 | 看至 25% 的次数数组。 |
| `video_p50_watched_actions` | 可选（视频广告建议） | 事件数组 | 看至 50% 的次数数组。 |
| `video_p75_watched_actions` | 可选（视频广告建议） | 事件数组 | 看至 75% 的次数数组。 |
| `video_p95_watched_actions` | 可选（视频广告建议） | 事件数组 | 看至 95% 的次数数组。 |
| `video_p100_watched_actions` | 可选（视频广告建议） | 事件数组 | 看至 100% 的次数数组。 |


建议在 `actions` 中尽可能提供：`link_click`、`landing_page_view` 或 `omni_landing_page_view`、`complete_registration`、`purchase`、`first_recharge`、`add_to_cart`、`lead` 等事件。

视频广告还建议提供：`video_play_actions`、`video_p25_watched_actions`、`video_p50_watched_actions`、`video_p75_watched_actions`、`video_p95_watched_actions`、`video_p100_watched_actions`。各数组格式均为：

```json
[{"action_type": "video_view", "value": "7200"}]
```

#### `insight.actions` 与视频事件数组中支持的内容

每个数组元素使用以下结构：

```json
{"action_type": "purchase", "value": "10"}
```

| 子字段 | 必传情况 | 含义 |
| --- | --- | --- |
| `action_type` | 数组元素内建议必传 | Facebook 返回的事件类型。例如 `landing_page_view`、`purchase`、`complete_registration`、`first_recharge`、`add_to_cart`、`lead`、`video_view`。 |
| `value` | 数组元素内建议必传 | 对应事件的次数，必须是可识别的非负数；不是成交金额。 |

### 6.5 `siblings`：同组广告横向对比字段完整清单

`siblings` 是可选数组，用于比较同一广告组或同一投放目标下的其他广告；推荐有可比对象时传 2 条以上。它只用于**成效和文案的横向比较**，AI 系统不会下载或画面分析 sibling 的素材。

每个 sibling 顶层只传 `creative` 和 `insight`。`siblings[*].creative` 与 `siblings[*].insight` 的字段意义、格式和事件数组结构**与主广告对应对象完全相同**；不要把它理解为另一套较少字段的成效结构。可以按实际缺失情况省略可选字段，但为了得到有意义的横向比较，建议每条 sibling 至少提供本表列出的基础成效快照，并与主广告使用相同统计周期、相同归因口径。

| 字段路径 | 必传情况 | 类型 / 示例 | 字段含义与使用方式 |

| `siblings` | 可选 | 数组，例如 `[]` | 同一广告组或同一投放目标下的其他广告列表。没有可比广告时不传或传空数组。 |
| `siblings[*]` | 数组元素内建议必传 | 对象 | 单个同组广告的比较数据。建议每条都有 `creative` 与 `insight`。 |

| `siblings[*].creative.name` | 可选（强烈建议） | 字符串 | 同组广告名称，便于运营人员识别比较对象。 |
| `siblings[*].creative.creative_type` | 可选（强烈建议） | `image`、`video`、`carousel` | 同组广告的素材类型。此处仅用于比较标签，不触发素材下载校验。 |
| `siblings[*].creative.message` | 可选（建议） | 字符串 | 同组广告主文案，用于文案横向比较。 |

### 6.6 `metadata_json`：业务补充信息字段完整清单

这是可选对象，用于补充不改变核心投放合同的业务上下文。以下字段是系统当前会识别或建议使用的字段：

| 字段 | 必传情况 | 类型 / 示例 | 字段含义与使用方式 |
| --- | --- | --- | --- |
| `source` | 可选 | 字符串，例如 `external_ad_system` | 外部数据来源名称，用于排查和追溯。 |
| `product_name` | 可选（建议） | 字符串，例如 `Smart TV` | 商品 / 产品名称。系统会用它帮助识别广告主题和公开创意研究方向。 |

| `industry` | 可选（建议） | 字符串，例如 `consumer_electronics` | 所属行业，用于补充产品语境。 |

## 8. 错误处理、重试与轮询


| HTTP 状态 | 常见含义                             | 外部系统处理                                                               |
| ------- | -------------------------------- | -------------------------------------------------------------------- |
| `200`   | 幂等重放成功，或 GET 查询成功                | 读取响应；POST 时复用返回的 `analysis_id`。                                      |
| `202`   | 新任务已受理                           | 保存 `analysis_id`，开始轮询。                                               |
| `400`   | 请求校验失败                           | 根据 `data.errors` 或 `message` 修正 JSON 后，以新的 `external_request_id` 重发。 |
| `401`   | 鉴权失败                             | 检查 token 和传递方式；不要在工单中泄露 token。                                       |
| `404`   | `analysis_id` 不存在                | 核对保存的 ID 和请求环境。                                                      |
| `409`   | 同一个 `external_request_id` 对应不同数据 | 新数据改用新的 `external_request_id`。                                       |
| `503`   | 队列暂时不可用                          | 用**原 ID + 原 JSON**重试 POST，服务端会复用任务。                                  |


推荐轮询策略：第一次 GET 等待约 2 秒；随后每 3～5 秒一次；等待 2～5 分钟后，页面可以显示“分析仍在进行中”，但仍应允许用户继续刷新同一个 `analysis_id`。不要把轮询超时理解为任务失败。

## 9. 联调验收清单

请至少完成以下验收：

- [ ] 鉴权：使用 Bearer Token 成功创建和查询任务。
- [ ] 图片广告：提供 `creative.image_url`，成功创建任务。
- [ ] 视频广告：提供 `creative.video_url`，成功创建任务；最好同时提供播放分位数据。
- [ ] 轮播广告：提供按顺序排列的 2～10 个 `creative.image_urls`。
- [ ] CBO：`campaign.daily_budget` 有值、`adset.daily_budget=null`，不传 `adset.bid_strategy`。
- [ ] ABO：`adset.daily_budget` 有有效金额时可传 `adset.bid_strategy`。
- [ ] 成效：至少传消耗、展现、链接点击和购买/注册等 `actions`。
- [ ] siblings：若有同组广告，传 2 条可比 `creative + insight` 对象，不带素材 URL。
- [ ] 幂等：对相同 JSON 连续 POST 两次，第二次得到 HTTP 200 且 `idempotent_replay=true`。
- [ ] 冲突：相同 `external_request_id` 修改业务数据后得到 HTTP 409。
- [ ] 轮询：保存 POST 返回的 `analysis_id`，查询直到 `succeeded` 并展示 `result`。
- [ ] 降级：主素材地址不可下载时，确认任务仍可基于数据/文案完成，且素材部分如实提示限制。

## 11. 问题反馈与确认回执

出现问题时，请提供：

1. `external_request_id`；
2. `analysis_id`（若已经创建）；
3. 请求时间（含时区）；
4. HTTP 状态码；
5. 完整响应 body；
6. 脱敏后的请求 JSON（不要携带 token）。

请外部系统在联调前确认：

1. 能按 `POST /analysis-jobs` 创建、`GET /analysis-jobs/{analysis_id}` 查询的流程接入；
2. 能为每次新分析生成唯一 `external_request_id`，且重试可保持请求 JSON 一致；
3. 能提供 AI 系统服务器实际可下载的图片/视频 HTTP(S) URL；
4. 能提供 `campaign`、`adset`、`creative`、`insight` 及尽可能完整的 `actions`；
5. 能区分 CBO 与 ABO，并按本文传递预算、出价和开关时间；
6. 可提供 1 份图片广告、1 份视频广告和（如有）1 份轮播广告的真实或脱敏联调数据。
