# 广告自动化投流流程说明

## 1. 文档目的

本文用于说明本项目的广告自动化投流主流程，重点回答以下三个问题：

1. 第一步先做什么。
2. 每一步系统会产出什么结果。
3. 这些结果在后续环节中起什么作用。

该系统的设计原则不是“完全无人投放”，而是“AI 提效 + 人工审核 + 可控发布”。

## 2. 流程总览

整体流程如下：

`工单录入 -> Campaign 建立 -> 落地页分析 -> AI 选题 -> 人工选题 -> AI 文案 -> 文案审核 -> 图片素材 -> 素材审核 -> 视频素材（可选） -> 视频审核 -> Meta 投放计划草案 -> 发布包预检查 -> 人工审批 -> Dry Run / 创建暂停广告 -> 正式激活 -> 状态同步 -> 数据回流`

## 3. 分步骤说明

| 步骤 | 这一步做什么 | 产出结果 | 结果的作用 |
| --- | --- | --- | --- |
| 第 1 步：录入投放工单 | 运营把原始投放需求录入系统，内容一般包括项目名、国家、投放事件、人群、产品名、落地页链接等。 | `WorkOrder` 工单记录；同时系统会解析出结构化字段，如 `project_name`、`country`、`event_name`、`audience_description`、`landing_url`。 | 这是整个流程的入口。后续 Campaign、选题、文案、投放配置都会复用这里的原始需求和解析字段。 |
| 第 2 步：从工单创建 Campaign | 系统把工单转成一次正式投放任务，并将工单上下文写入 Campaign。 | `Campaign` 投放项目主记录；包含项目名、投放目标、产品信息、人群描述、预算备注，以及 `metadata.work_order`。 | Campaign 是后续所有 AI 生成、素材生成、审核、发布和回流的主索引对象。 |
| 第 3 步：分析落地页 | 系统抓取工单中的落地页链接，提取标题、描述、正文摘要、标题层级、链接等信息。 | `LandingPageSnapshot` 落地页快照；同时写回 `campaign.metadata.landing_page`。 | 让后续 AI 不只看工单，还能理解实际承接页内容，减少文案和素材与落地页不一致的问题。 |
| 第 4 步：AI 生成投放选题 | 系统基于 Campaign、工单信息、落地页内容和补充 signals，生成 1 到 3 个投放角度。 | `Topic` 选题列表；每条包含标题、投放角度、目标人群、卖点、风险提示、生成理由、评分。 | 为文案和素材提供方向，避免直接从空白开始写广告。 |
| 第 5 步：人工选择选题 | 运营或审核人从候选选题中选择一个主方向，不合适的可以驳回。 | 选中的 `Topic` 状态变为 `selected`；不采用的主题可标记为 `rejected`。 | 把 AI 的发散结果收敛成一个明确执行方向，作为后续文案生成依据。 |
| 第 6 步：AI 生成广告文案 | 系统根据选题生成广告正文、主文案、标题、描述、CTA 等内容。 | `CopyDraft` 文案草稿；包含 `body`、`primary_text`、`headline`、`description`、`cta`、版本号等。 | 这是图片素材、视频脚本和 Meta 广告创意的直接文本来源。 |
| 第 7 步：人工审核或修订文案 | 对文案进行确认，不合适的可提出反馈并生成新版本。 | 审核通过后，文案状态为 `approved`；如果需要修改，会生成新的 `CopyDraft` 版本。 | 确保对外投放文案符合业务要求、平台规范和品牌表达。 |
| 第 8 步：生成图片素材 | 系统先根据文案生成图片 brief，再调用图片生成能力生成素材，并保存素材地址或存储键。 | `CreativeAsset` 图片素材记录；包含图片 URL、prompt、alt_text、尺寸、存储位置等。 | 用作广告主图，也可作为后续视频生成的参考图。 |
| 第 9 步：人工审核图片素材 | 审核图片是否符合卖点表达、视觉规范和合规要求。 | 审核通过后，素材状态变为 `approved`；不通过则标记 `rejected` 或 `needs_revision`。 | 只有合格素材才进入投放或视频制作环节。 |
| 第 10 步：生成视频脚本与视频任务（可选） | 如果本次投放需要视频，系统会基于已选图片、文案和落地页内容生成 storyboard，并创建视频任务，再向视频供应方发起生成。 | `VideoStoryboard` 视频分镜方案；`VideoAsset` 视频任务及生成结果；成功后会保存视频 URL 和存储信息。 | 让投放既支持图文广告，也支持视频广告；视频也可进入 Meta 广告投放。 |
| 第 11 步：人工审核视频 | 对生成的视频内容、节奏、字幕、镜头表达进行确认。 | 审核通过后，视频状态变为 `approved`；失败或不合适可驳回或重做。 | 确保视频素材达到可以投放的标准。 |
| 第 12 步：生成 Meta 广告创意草案 | 系统把文案、图片或视频、落地页链接、Page、Ad Account 等信息组装成 Meta 广告创意请求草案。 | `AdCreativeDraft`；可看到 headline、primary text、media type、目标链接，以及对应的 Meta 请求体预览。 | 这一层把内部业务内容转成 Meta 可以理解的广告创意结构。 |
| 第 13 步：生成 Meta 投放计划草案 | 系统在创意草案基础上，继续组装 Campaign、Ad Set、Ad Creative、Ad 四层投放结构，并自动推断地域、人群、目标事件、预算占位等。 | `AdsPlanDraft`；包含 `campaign_payload`、`adset_payload`、`creative_payload`、`ad_payload`、`warnings`。 | 形成正式投放前的完整计划包，便于检查目标、定向、预算和素材是否匹配。 |
| 第 14 步：生成发布包并做预检查 | 系统会检查是否已有落地页、文案、素材、Page、Ad Account、Pixel、预算等关键要素；图片会先换成 Meta 可用的 `image_hash`。 | `PublishJob` 发布任务，状态先为 `queued`；同时记录 `preflight_warnings` 和待审核标记。 | 这是发布前的总装与风控步骤，避免带着缺失字段直接发到 Meta。 |
| 第 15 步：人工审批发布任务 | 发布任务必须先过人工审核，系统才允许真正执行。 | 发布任务的 `review_status` 变为 `approved`、`rejected` 或 `needs_revision`。 | 把最终投放动作从“AI 自动生成”切换为“人工批准后执行”，满足管理和风控要求。 |
| 第 16 步：执行发布，先以暂停状态创建广告 | 系统调用 Meta 接口，依次创建 Campaign、Ad Set、Ad Creative、Ad。默认创建为 `PAUSED`，并支持 Dry Run。 | 发布成功后，`PublishJob` 状态为 `published`；保存 Meta 返回的 `campaign_id`、`adset_id`、`ad_creative_id`、`ad_id`。 | 先把广告结构创建出来，但不立即放量，给团队保留最后一次检查窗口。 |
| 第 17 步：人工确认后正式激活 | 审核确认无误后，系统再把 Campaign、Ad Set、Ad 从 `PAUSED` 改成 `ACTIVE`。 | 发布任务中记录 `activation` 信息，投放状态更新为 `active`。 | 这是“真正开始投流”的动作，确保上线是显式确认而不是默认自动放量。 |
| 第 18 步：投放状态同步 | 系统可定期从 Meta 拉回 Campaign、Ad Set、Ad 的状态，例如审核中、已激活、已暂停、被拒。 | 发布任务中的 `meta_status`、`delivery_status`、`meta_review_status`。 | 让运营知道广告当前是待审、投放中、暂停还是被平台驳回。 |
| 第 19 步：效果数据回流 | 系统从 Meta 拉取或人工录入每日数据，如花费、曝光、点击、CTR、CPC、转化等。 | `InsightDaily` 日报数据；同时在发布任务中沉淀 `meta_insights` 摘要。 | 形成复盘依据，为下一轮选题、文案、素材和投放优化提供数据输入。 |

## 4. 每一步的核心产物清单

| 阶段产物 | 含义 | 主要被谁使用 |
| --- | --- | --- |
| `WorkOrder` | 原始投放需求和解析字段 | Campaign、选题、投放计划 |
| `Campaign` | 一次正式投放任务的主档案 | 全流程共用 |
| `LandingPageSnapshot` | 落地页分析结果 | 选题、文案、视频脚本 |
| `Topic` | 投放角度候选 | 文案生成 |
| `CopyDraft` | 广告文案版本 | 图片、视频、Meta 创意 |
| `CreativeAsset` | 图片素材 | 图片广告、视频生成、Meta 创意 |
| `VideoAsset` | 视频素材 | 视频广告发布 |
| `PublishJob` | 发布执行单 | 审批、执行、状态同步 |
| `InsightDaily` | 每日投放数据 | 复盘和优化 |

## 5. 当前流程中的关键控制点

为了让流程适合上线和过审，系统当前内置了几个控制点：

1. 不是所有内容自动直发，关键节点保留人工审核。
2. 发布任务必须先审批通过，才能真正执行。
3. Meta 广告默认先按 `PAUSED` 创建，而不是直接开始放量。
4. 系统支持 `Dry Run`，可以先验证请求结构，再切换真实投放。
5. 发布后还能继续执行状态同步和数据回流，方便复盘与风控。

## 6. 适合向领导汇报的一句话总结

这套系统的本质，是把广告投放中“工单整理、信息理解、选题、文案、素材、发布准备、状态回收、数据回流”这一条高重复链路标准化，并在真正投放前保留人工审核和显式激活机制，从而实现“提效但不失控”的自动化投流流程。
