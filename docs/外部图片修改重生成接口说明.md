# 外部图片修改重生成接口说明

本文档给外部投放系统开发人员使用，说明如何基于上一次图片生成任务的 `job_id` 和修改意见再次生成图片。

## 1. 基础信息

接口基础地址：

```text
https://ai.ggcss.xyz
```

统一鉴权方式沿用 `AI_ADS_ACCESS_TOKEN`：

```http
Authorization: Bearer <AI_ADS_ACCESS_TOKEN>
Content-Type: application/json
```

也支持把 token 放在 URL 查询参数中：

```text
?ai_access_token=<AI_ADS_ACCESS_TOKEN>
```

## 2. 创建原始图片任务

修改重生成必须基于已经成功的外部图片生成任务。原始任务仍使用现有接口：

```http
POST https://ai.ggcss.xyz/api/v1/integrations/image-generation/images
```

创建成功返回 HTTP `202`：

```json
{
  "code": 1001,
  "message": "processing",
  "data": {
    "job_id": "source-job-id",
    "status": "processing",
    "count": 1,
    "size": "1:1"
  }
}
```

外部系统需要保存 `data.job_id`。只有当该任务轮询结果为 `succeeded` 后，才可以用它创建修改重生成任务。

## 3. 创建修改重生成任务

接口：

```http
POST https://ai.ggcss.xyz/api/v1/integrations/image-generation/jobs/{source_job_id}/revisions
```

路径参数：

| 参数 | 类型 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| `source_job_id` | string | 是 | 上一次成功图片生成任务返回的 `job_id`。 |

请求参数：

| 参数 | 类型 | 是否必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `external_request_id` | string | 否 | 无 | 外部系统请求 ID，用于幂等。最大 128 字符。 |
| `feedback` | string | 是 | 无 | 修改意见，1 到 2000 字符。 |
| `source_image_index` | integer | 否 | `1` | 使用源任务里的第几张图片作为原图。 |
| `count` | integer | 否 | 继承源任务，最少为 `1` | 本次重生成图片数量，范围 `1` 到 `5`。 |
| `size` | string | 否 | 继承源图片 | 图片比例或尺寸标识，例如 `1:1`、`9:16`。 |
| `model_id` | string | 否 | 继承源任务 | 指定图片模型；不传时沿用源任务模型。 |

请求示例：

```json
{
  "external_request_id": "image-revision-20260707-001",
  "feedback": "保留人物和产品位置，把背景改成红色，并让光线更明亮",
  "source_image_index": 1,
  "count": 1
}
```

创建成功返回 HTTP `202`：

```json
{
  "code": 1001,
  "message": "processing",
  "data": {
    "job_id": "revision-job-id",
    "status": "processing",
    "count": 1,
    "size": "1:1",
    "source_job_id": "source-job-id",
    "mode": "generate"
  }
}
```

返回字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `data.job_id` | string | 新的修改重生成任务 ID。后续轮询使用这个新 ID。 |
| `data.source_job_id` | string | 本次修改所基于的源任务 ID。 |
| `data.mode` | string | 实际生成模式，`edit` 表示走图生图编辑，`generate` 表示走文生图降级。 |

## 4. 查询修改重生成结果

结果仍使用现有图片任务查询接口，不需要新查询接口：

```http
GET https://ai.ggcss.xyz/api/v1/integrations/image-generation/jobs/{job_id}
```

这里的 `{job_id}` 是修改重生成接口返回的新 `revision-job-id`。

处理中返回：

```json
{
  "code": 1001,
  "message": "processing",
  "data": {
    "job_id": "revision-job-id",
    "status": "processing",
    "count": 1,
    "size": "1:1",
    "source_job_id": "source-job-id",
    "mode": "generate",
    "images": []
  }
}
```

成功返回：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "job_id": "revision-job-id",
    "status": "succeeded",
    "count": 1,
    "size": "1:1",
    "source_job_id": "source-job-id",
    "mode": "generate",
    "images": [
      {
        "index": 1,
        "url": "https://ai.ggcss.xyz/storage/images/external_image_generation/revision-job-id/1.png",
        "prompt": "Original prompt\n\n修改要求：保留人物和产品位置，把背景改成红色，并让光线更明亮"
      }
    ]
  }
}
```

失败返回：

```json
{
  "code": 5001,
  "message": "image generation failed",
  "data": {
    "job_id": "revision-job-id",
    "status": "failed",
    "count": 1,
    "size": "1:1",
    "source_job_id": "source-job-id",
    "mode": "generate",
    "images": [],
    "error": "provider error message"
  }
}
```

## 5. 图生图与降级行为

系统会先从源任务结果中读取原图的 `storage_key`，再把原图转换为内部 data URL，交给图片供应商。

当网关图片编辑能力开启，并且底层模型支持 `/images/edits` 时，系统会走图生图编辑：

```text
原图 + feedback -> /images/edits -> 新图片
```

当未开启编辑能力，或者当前图片供应商是 `volcengine`、`placeholder` 等不支持编辑的供应商时，系统会自动降级为文生图重生成：

```text
原 prompt + 修改要求 -> /images/generations -> 新图片
```

默认配置为：

```env
MODEL_GATEWAY_IMAGE_EDIT_ENABLED=false
MODEL_GATEWAY_IMAGE_EDIT_PATH=/images/edits
MODEL_GATEWAY_IMAGE_EDIT_MODEL=
```

因此上线默认不会改变现有图片生成行为。确认网关和模型支持图片编辑后，再把 `MODEL_GATEWAY_IMAGE_EDIT_ENABLED` 改为 `true`。

## 6. 调用建议

1. 外部系统保存每次返回的 `job_id`，后续可以继续基于最新结果再次 revision。
2. `feedback` 尽量写成具体修改项，例如“保留产品位置，只修改背景颜色”，不要只写“重新生成”。
3. 如果只想修改某一张图，传对应的 `source_image_index`；不传时默认使用第 1 张。
4. 每次 revision 都会创建新的 `job_id`，不要用源任务 ID 查询新结果。
5. 接口调用失败时先判断 `code` 和 `message`，不要只判断 HTTP 状态。
6. 不要把真实 token 写进前端代码、日志、截图或公开文档。
